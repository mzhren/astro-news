**主题：11/13 一天里，两道"专用"的堤坝同时被拆——OpenAI 把机器人团队拆进通用研究，理由是一段 Codex 会话就能开机器人；Mirendil 拿 10 亿美元证明一个研究员加一堆 agent 能从零预训练出模型；而 CoRL 的两个奖，一个把仿真器换成了可微世界模型（算力降千倍），一个把上下文塞进了参数里**

---

## 主条目

### 1. OpenAI 解散独立机器人团队：一段 Codex 会话，74.8% 的成功率

- **11/13 周五美东，《财富》独家，OpenAI 向《财富》确认**：独立的机器人团队已解散。**机器人研究团队并入公司主研究团队，向首席研究官 Mark Chen 汇报**；**应用机器人与硬件团队并入 Applied 组织，向总裁 Greg Brockman 汇报**。**未披露涉及人数，也没有官方博客**。
- **调整发生得很突然**：OpenAI 早前已报名本周在奥斯汀举行的 CoRL，会议 App 与展厅平面图上留了 **208 号展位**——《财富》记者到场时，展位空着，**OpenAI 的标识也不见了**。前团队成员站过的地方还围着人。
- **官方给的理由是"路线变了"，不是"退了"**：2026 年初，研究人员认为推进机器人的最佳路径是**建立在 Sora 这类视频模型之上**（生成逼真视频必然隐含对物理世界的某种理解）；但此后**通用前沿模型（含 GPT-6 Astra）已被证明可直接用于机器人**。发言人强调机器人仍是长期核心愿景，拆团队是"最快的方式"。
- **支撑这个判断的是一组外部数据**（英伟达 **10/14** 的研究）：

| 项目 | 数值 |
|---|---|
| 基准 | **RoboLab-120**，模拟抓放，**无机器人专项训练** |
| 控制器 | **GPT-6 Astra 跑在 Codex 会话里** |
| 成功率 | **74.8%**｜榜单最佳专用机器人模型 **Lakeside 51.0%** |
| 代价 | 最佳配置约 **$36.40 token / 次尝试**；最简版本**单次模型调用 18.56 秒** |
| 参照 | 同一基准 Runway 上周的 Praxis-1 也用过 |

- **两次"拆"的历史**：2020 年首次关停机器人团队，联创 Zaremba 归因于**机器人数据不足**、走别的路更快通向 AGI；2024 年重建并牵手 Figure；**2025 年 2 月 Figure 终止合作**自研机器人大脑。Altman 现在的口径是**自研人形、2027 年首次公开展示**。同期背景是削减"side quests"：上季度运营亏损据报 **109 亿美元**，公司在冲新一轮融资、筹备 2027 年初 IPO。
- **为什么值得关注**：这是**"专用具身大脑"这条估值叙事第一次被一家前沿实验室公开降级**。过去两年，一大批机器人创业公司的融资前提是"机器人需要自己的大脑、需要自己的空间智能"，OpenAI 现在把这句前提换成了"机器人是通用智能的下游应用"。CMU 机器人研究所助理教授 **Guanya Shi** 的说法最直接：这意味着 OpenAI 不再把机器人当成"一个特殊问题"；但他同时指出**能跑在机器人自身计算机上、不依赖常连网的小模型仍然必要**——这正好是 18.56 秒/次那条数据的含义：**能力强不等于能上机**。
- **反方也给了硬理由**：MIT 教授、Walden Robotics 联合创始人兼 CEO **Russ Tedrake** 认为机器人公司仍有 AI 实验室没有的东西——**机器已经在工厂这类真实场地积累工作经验与数据**，这些部署经验让它们更贴具体工位与任务。把这两句放在一起看，本期真正的分界线不是"通用 vs 专用"，而是**"谁的循环更快"**：通用模型赢在零样本起步，专用系统赢在数据回流。
- **对 coding 侧的传导常被忽略**：这条的对照组是 **Codex 当机器人控制器**——一个为写代码设计的 agent harness，被直接拿去做抓放。它和 11/07 期清华×Berkeley 的 uni-robot-agent（把 Codex/Claude Code 当机器人 runtime）、11/12 期苹果 AMP1（通用模型留在控制回路、持久 Python 解释器写码）是同一条线的第三次确认。**代价同样一致：单次成功要几十秒到几百秒、每次几美元到几十美元**，离"1kHz 控制回路"还差两三个数量级。

### 2. CoRL 2026 双料最佳论文：一个把仿真器换掉，一个把上下文塞进参数

- **11/11 Awards & Farewell 揭晓**（会议 11/9–12 奥斯汀；只有最佳论文与最佳学生论文两个奖，今年入围 6 篇，**2 篇获奖、4 篇入围**）。11/13 中文圈出了完整的六篇盘点。
- **最佳论文：SuperMimic**（UC Berkeley；Qiayuan Liao、Yiyang Shao、Junfeng Long、Kevin Zakka、Roberto Horowitz、Pieter Abbeel、Koushil Sreenath｜arXiv 2610.28480）。命题是"**用一个可微世界模型扩展人形全身控制**"。

| 项目 | 数值 |
|---|---|
| 被替代的对象 | 物理仿真器 + 大规模 RL（对标 **SONIC，约 2.1 万 GPU 小时**） |
| 做法 | 从仿真日志**拟合共享刚体动力学**（与动作无关的可微世界模型）；策略在模型内做**短时程"想象推演"**，用**解析梯度**更新，绕开仿真器不可微 |
| 基准 | **12.9 万条动作** |
| 结果 | **单张 H100 跑 3 小时**，超过 SONIC 的 **128×L40、168 小时**集群模型；**算力降超千倍** |
| 质量 | 失败动作 **179 → 25** |
| 落地 | 策略直接部署**宇树 G1**，完成高难度**翻滚与跳跃** |

- **最佳学生论文：RoboTTT**（NVIDIA / Stanford / UT Austin；Yunfan Jiang、Yevgen Chebotar、Ruijie Zheng、Fengyuan Hu、Yunhao Ge、Jimmy Wu、Tianyuan Dai、Scott Reed、李飞飞、Yuke Zhu、Linxi "Jim" Fan｜arXiv 2607.15275）。命题是"**机器人策略的上下文扩展**"。
  - **问题**：长上下文卡在两头——KV cache 撑大推理延迟，RNN 又容量不够。
  - **做法**：**记忆不放进上下文，放进参数**。引入"**快权重**"+**测试时训练（TTT）**，每步用内层梯度把历史写进参数；工程上用**序列动作强制**与**截断反传**，把上下文训到 **8000 步**。
  - **结果**：真机装配任务完成率 **79%**（单步基线 **42%**）；支持把**人类视频当一次性模仿**；还支持把**失败轨迹当上下文、把纠正当目标**做蒸馏，**100 条轨迹的利用率是标准 DAgger 的 3 倍**。
- **四篇入围同样值得记**：**Play2Perfect**（Stanford，22 自由度 **Sharpa 五指手**，任务无关的"先玩后装"预训练，样本效率 **33 倍**，**0.5mm 紧配合插接零样本 sim-to-real 60%**）；**GRAIL**（NVIDIA/UCLA，用视频世界模型生成带米制尺度与物理交互的 4D 人机轨迹、再动作重定向，产出 **35,000+ 段**物理校验素材，真机演示桌面取物、越障、上楼梯）；**DISCO**（CMU/Stanford，渐进加宽 **MCTS** + 策略-价值蒸馏做长程多物体重排，收敛后策略可脱离搜索部署）；以及一篇**基准审计**（TTIC/Chicago/Argonne）——**9000 万参数探针、没有语言编码器也能逼近 LIBERO 的 SOTA**，多数基准不报方差，分布内轻微扰动就大幅掉分。
- **为什么值得关注**：这两篇奖指向同一件事——**具身智能的成本结构正在被改写，而且改的不是"模型更大"，是"少花"**。
  - **SuperMimic 砍的是仿真**。强化学习训人形之所以贵，是因为每一步都要跑一个不可微的物理引擎；把仿真日志"蒸馏"成一个可微的动力学代理，梯度就能直接算。代价是**保真度**：代理模型在训练分布外会失真，所以它天然适合"已有很多仿真日志"的团队，而不适合从零探索新任务。
  - **RoboTTT 砍的是上下文窗口**。把历史写进快权重，等于用"每步一次小梯度更新"换"每步读一遍长上下文"。这条路和赵行在 11/13 期讲的"给模型配时钟"是同一个问题的两种解法——**长程任务里，记忆的存放位置决定了延迟**。
  - **那篇基准审计是最该被记住的**：如果 9000 万参数的探针不看指令就能接近榜首，那么这个榜首衡量的很可能不是"看懂任务并泛化"，而是"在这个数据分布上拟合得多好"。**看机器人榜单时，先看它有没有报方差。**

### 3. Mirendil 10 亿美元 A 轮：一个研究员 + 一堆 agent，3.5 个月从零预训练

- **11/12 官宣**（PR Newswire）：**10 亿美元 A 轮**，**Kleiner Perkins 与 Clearlake Capital 领投**，Battery Ventures、Doerr Capital、Gil & Co、**Google**、M13、Pear VC、S32 等参投。**估值未披露**（WSJ 报约 **50 亿美元**，公司口径不给）。距 6 月 **2 亿美元种子轮**（a16z 与 KP 领投）不到五个月。
- **它拿得出的唯一硬实验**：

| 项目 | 数值 |
|---|---|
| 预训练 | **Mirendil-Base**（competitive coding 模型），**从零**训练 **3.5 个月** |
| 算力 | **不到 1000 万美元**（口径含实验、最终 run、agent token 支出、数据处理） |
| 人力 | **一个研究员 + agents** |
| 代码 | **agents 写了 99% 以上** |
| 后训练 | 得到 **Fern**，上下文 **1000 万 token**（约 **50 万行代码**） |
| 产品 | **Lor**，私测（邀请制） |

- **Lor 是"把研究当工程派单"**：用户给目标，**数百个 agent** 写代码、跑实验、看结果、接着改，可以连着跑几天；出错自己修而不是等人；**自己去申请 GPU 机器、干完释放**；关掉笔记本任务继续；每个 agent 的进度可看、可停。官方举的例子包括：隔夜跑一批实验并写报告、审一个仓库的安全 bug 并**每个修复开一个 PR**、在 8 张卡上复现论文里的一张表格并解释数字为何不同。一次测试里 **102 个 agent 从 100 个 PyTorch PR 搭训练环境，平均 8 分钟一个**。Lor 可调 Anthropic、OpenAI、Google、xAI、Meta 的模型，也调自家的；私测期免费。
- **团队与口径**：CEO **Behnam Neyshabur**（前 DeepMind Gemini 团队、后 Anthropic）、CTO **Harsh Mehta**、联创 Shayan Salehian（xAI 早期成员）与 Tara Rezaei；6 月成立时 20 人。官方一句话概括赌注：**"当 agent 干手工活时，团队规模不再限制你能建什么。"**
- **为什么值得关注**：这是我 10/28 期那条 **Fern 0.1**（当时"未开放、可申请早期访问"）的兑现，但重点不在模型，在**计费单位**。过去一年 coding agent 的产出单位是 **PR / 工单**；Lor 把它换成了**实验**——一次交付不是"改好了这段代码"，而是"这 20 组超参跑完了、结论在这"。这带来一个不太舒服的推论：**如果 agent 能自己跑实验，那么"研究"这件事的瓶颈就从人手的数量，变成了判断力的质量**——你得知道该问什么、以及哪条曲线是真的。
- **但要打折看**：训练成本、上下文长度、成功率**都是公司自报，无第三方评测**；Lor 仍是邀请制私测；"数百 agent 跑几天"目前只见到**单次构造性测试（102 agent/100 PR）**，没有连续的科研产出被复现。这条和 11/12 期 AWS Emulator（"未编写未审查"）是同一类叙事——**能力声明走在可验证证据前面**，值得跟，不宜转发结论。

### 4. llama.cpp 与 ggml 同时到 1.0：本地 AI 的地基第一次有了兼容性契约

- **11/13，ggml-org 同时发布 llama.cpp v1.0.0 与 ggml v1.0.0**。前一个带号版本 **v0.9.0 才是一周前的 11/4**；对应滚动构建 b12359。Hugging Face 联创兼 CEO **Clément Delangue** 发帖宣布（核心团队 2026 年初加入 HF）。
- **1.0 的实质是"版本号变成承诺"**：项目长期只有近乎每日的构建 tag，下游靠钉死某个 tag 活着，没有公开的兼容策略。1.0 给出的规则可以印在一行里——**破公共 C API 就动大版本；向后兼容的新增（新功能/新后端/新模型家族/新 API）动小版本；纯修 bug 只动补丁号**。官方明确说，很多下游应用已经依赖这些接口，"灵活但稳定的 API"现在是头等大事。**但没有给旧大版本的支持窗口**，需要长期稳定的团队仍得自己钉版本、自己测。
- **它用这个大版本号清了一次库（升级会真的编译不过）**：删掉 **35 个废弃函数**、`llama_set_warmup`、`defrag_thold` 设置及其命令行旗标；**NextN 投机解码 API 移入主头文件**；一个 context-state 函数改名；ggml 同步移除废弃 API 与 legacy `DIAG_MASK` 算子。**RPC 升到 v9，会拒绝不兼容的 peer**——跨机跑 ggml 的，升级前先核对各进程协议版本，别在运行时才发现不匹配。
- **最该先读的是 server 安全段**：新增**未认证工具与私有媒体 URL 的显式 opt-in**；修 **CORS origin 处理、DNS rebinding、CORS 代理的 SSRF 路径**；**HF token 限定只发往 huggingface.co**；**MCP 工具调用在客户端断连或超时时被取消**。这一串恰好对应"llama-server 已经不在单机上"的现实——它在网络上、接着工具、在抓外部媒体。**新默认值本身就是这次的功能**。
- **性能侧只给了机制、没给数字**：**FP8 KV cache**（长文本省显存）、**MoE 专家的 host-memory cache**（把专家权重放主机内存）；后端同时覆盖 CUDA / Metal / Vulkan / SYCL / OpenCL；**8 个分发渠道**（Linux/macOS/Windows/Android/iOS 预编译、Docker、Debian、Homebrew、conda-forge、MacPorts、Winget、XCFramework）。新模型支持里有 **Kimi K3.1 Pro**（文本+视觉，**1.56TB**）、Ripple、MageVL-Cowork、Drama-3 TTS、Gemma 4 流式音频输入。
- **为什么值得关注**：这件事和 coding 的关系不在跑分，在**私有化部署的可行性**。Ollama、LM Studio、Brave Leo、Opera 的本地模型、Sourcegraph Cody 都建在它上面；一个能被钉住、能预判破坏性变更的推理底座，才敢被写进企业内部的 coding agent 方案。反过来说，**"1.0 不等于更快、也不等于更聪明"**——它只是让"升级会不会炸"这个问题第一次有了答案。另外那条 K3.1 Pro 的注脚挺有意思：**工具已经就绪，但 1.56TB 没地方放**，本地推理的瓶颈正从软件转到内存。

### 5. Claude Code 的 Code Mode 与五家 CLI 同日发版：工具调用从"说"变成"写"

- **11/12 Claude Code 2.1.323** 引入**实验性 Code Mode（需主动启用）**：由 Claude **写 JavaScript 直接调用工具**，而不是逐轮用自然语言描述工具调用，目的是**省掉中间的解析开销**。同版本**移除 `subagentStatusLine` 设置**——子 agent 行统一用默认外观，旧配置仍能加载但**不再生效**（这类"能加载但不生效"的配置是最容易静默踩坑的一类）。**官方没有给 Code Mode 的省 token 或提效实测。**
- **11/13 的 2.1.325 是补丁，但补的都是硬问题**：修 **zstd 压缩响应解码的安全问题**；修子 agent 自带模型在 `opusplan` / `haiku` 设置下被错移到 plan-mode 模型、以及用主会话模型去估算文件读取与 MCP 结果大小；修**大量第三方网关与 Foundry 上每轮都报 context length 错误而不是触发压缩**；修**恢复会话丢最近轮次**（进程非正常退出后）；修沙箱内 `git checkout` / `git stash` / autostash pull 无法更新 `.claude` 下受保护文件。节奏参考：这是 2026 年第 **263** 个 release，平均 **1.9 天**一个，近一个月 21 个。
- **Codex CLI 0.169.0（11/13）的重点是信任边界**：可选终端工作区支持**多个侧聊标签**、Agent 指挥中心可按名称/提示预览/工作目录**搜索旧任务**、自定义模型 provider 可在终端里管理；"清空上下文并实施"现在把**完整获批计划**交给新会话，**交接失败保留当前会话**。安全侧写得很清楚：**`codex exec` 即使带 `--sandbox workspace-write`，在未信任目录里仍禁用项目配置与 MCP 服务器**，要显式信任必须 `--trust`。**不能凭 sandbox 参数判断工具会不会被加载**。
- **同日一起发的还有**：GitHub Copilot CLI 1.0.111、opencode 2.3.0、Antigravity CLI 1.5.8、Grok Build 1.0.85。
- **为什么值得关注**：Code Mode 是**工具调用协议的一次结构性改动**——把"模型输出一段结构化 JSON，harness 解析，再执行"换成"模型输出一段可执行代码，运行时自己调"。它省的是解析与多轮往返，换来的风险是**执行面变大**（能写 JS 就能写循环、能拼字符串）。这和 2.1.325 那条 zstd 解码安全修复、以及 Codex 那条"未信任目录禁 MCP"是同一件事的三个面：**harness 越强，边界越要写死**。
- **别把它读成"coding 又进了一步"**：五家同日发版更像是**版本节律的巧合**（各家都在周更/双日更），而非协同。真正需要动作的是两件小事：①升级前查一次 `subagentStatusLine` 之类"仍加载但不生效"的配置；②如果你在第三方网关或 Foundry 后面跑 Claude Code，2.1.325 之前的版本会**每轮报错而不压缩**，这条值得立刻升。
