**本期主线**：**这一周，五件事都在改"算不算做完"的定义。**

同一个 agent，按分项算 78.1%，按"MUST 全过"算 29.4%；同一批模型，测试过 63%，任务交付 7.9%；同一台机器人，熟悉动作 93.75%，需要判断物体轻重 2.4%；同一段 RTL，只有过了形式化等价验证的 14% 才敢送厂。**能力没变，尺子一变，数字全变。**

## 一、SWE-CoWork：模型测试过了 63%，活只干完 7.9%

**事件**（论文 arXiv 2611.20218，**11/15 提交**，26 位作者，Xinping Lei 牵头；The Decoder 11/22 报道，本期首收）

过去两年 coding benchmark 的默认设定是：给 agent 一个清楚的 issue 加一个失败的测试，看它能不能把测试弄绿。SWE-CoWork 把这套拆了——它把 agent 放进一家**模拟软件公司**，让它当员工。

- **101 个开发任务**，分布在 **101 个真实仓库**，覆盖 11 种语言、12 个应用域；
- 每个任务配 **26 个模拟同事**，各自掌握一部分需求，部分信息互相矛盾；同事由 `gpt-5.6-terra` 扮演；
- 需求共 **2,712 条，其中 2,217 条（82%）只存在于同事脑子里**，另 495 条散落在看板卡、设计文档、代码评审、历史聊天里；
- 起点只有一段**简短的交接说明**，不是完整规格；
- 预算 **8 小时/任务**，可用终端 + **17 个职场工具**（通过一个 MCP server 暴露）；
- 隐藏测试 **2,699 个 F2P + 562 个 P2P**，**全部通过才记成功**（reward 是 0/1）。

**数据（论文与项目仓库自报）**

| 指标 | Claude Opus 5.5 | GPT-6 Astra |
|---|---|---|
| F2P 通过率 | 63.84% | 62.91% |
| P2P 通过率 | 93.24% | 89.15% |
| **完整交付（101 个里）** | **6.93%（7 个）** | **7.92%（8 个）** |

失败不只在键盘上，链条每一段都在漏：

- **找对人 ≠ 拿到料**：Opus 5.5 首轮关于工单的提问，**93% 发给了对的人**，但它最终只拿到了同事手里 **64%** 的需求。前一个数字量的是"路由"，后一个量的是"获取"，中文稿常把两个混成一个。
- **被推迟的问题没人回头追**：轨迹分析里存在大量"先放着、后来忘了问"的问题。
- **需求拿到了，实现还是不全**：已经获得相关需求的样本里，仍有相当比例的实现停在半路。
- **自报"完成"不可信**：**31% 被 agent 标为已完成的需求，在测试里挂了。**
- **信息给全也救不了**：直接一次性把完整需求喂进去，Seed Evolving 与 GPT-6 Astra 的 F2P **+约 16 个百分点**，但**全任务完成率一点没动**。作者的结论是——瓶颈在"澄清→实现→验证→交接"这条端到端流水线，不是缺哪条事实。

**为什么值得关注**
这是第一份把"团队协作"当主变量、而不是当噪声的 coding benchmark，而且它给出的数字比任何榜单都更接近采购决策：**你可以放心让 agent 写补丁，但别指望它自己关单。** 对工程负责人，它把"给 agent 多少自治权"从感觉问题变成了可测问题——先看它在"要问人"的任务上能不能守住需求账本。它也和 Stripe 那套（见下条）互证：两份完全独立的评测，一个是组织维度、一个是接口维度，都指向同一个形状——**大部分正确，不等于完成**。

**要打的折**：同事是 LLM 模拟的，不是真人；任务书与工具全英文；这是 v1 预印本，另外 9 个模型的分项结果摘要里没拆开；"8 小时"是算力预算不是工期。

## 二、Stripe 开源 agent 评测：分项 78.1%，每条 MUST 全过只剩 29.4%

**事件**（Stripe 于 **11/19** 发布 benchmark 与 Forge 评测框架并开源；11/20–11/22 英文与中文圈扩散，本期首收）

Stripe 测的不是"能不能写代码"，是"能不能把 Stripe 接对"。它找了 **69 个真实场景**（24 个支付、26 个订阅、19 个 Connect 市场与平台），跑 **14 组"模型 × harness"组合**（Claude Code / Codex / OpenCode），每组 **276 次运行**（69 场景 × 2 次重复 × 2 个实验臂）。

两个实验臂是：**不带** Stripe 官方 agent 插件 / **带**插件（插件 = Skills + 一个 MCP server，含 `stripe_implementation_planner`、`search_stripe_documentation`、API search/details 等工具）。

每条场景对应一组评分项，逐条标 **MUST 或 SHOULD**（RFC 2119 口径），由独立 judge 模型判 pass/fail。于是有两个分数：

| 口径 | 含义 | 结果 |
|---|---|---|
| 平均分 | 通过项 / 全部项，给部分分 | **78.1%** |
| 严格通过率 | 所有 MUST 全过的运行占比 | **29.4%** |

**插件带来的增量（可量化，这是本期最实用的一组数）**
- **14 组全部提升，普遍 +3 到 +8 分**；
- **过时 API 参数引用率：7% → 1.3%**；
- **每次评测的联网搜索次数：1.26 → 0.05（-96%）**；
- 最好的一组 **GPT-6 Astra + Codex，严格口径 52.9%**（同组综合分 90.0%）。

**两个具体到疼的失败样本**
- 移动支付场景：GPT-6.1 Sol 无插件时写 `payment_method_types: ['card']`——这是旧写法，现行是 `automatic_payment_methods`（开启动态支付方式）。**代码跑得通，集成是过时的。**
- Radar 风控场景：Opus 5.5 只检查 `PaymentIntent.status === 'succeeded'` 就发货——**退款或争议之后订单照样出去了**。绝大部分代码正确，缺的那一行才是会让商户亏钱的那行。

Stripe 对根因的判断很直接：模型**偏向预训练语料里更常见的旧 API**，会漏关键特性、会幻觉。而通用 coding benchmark 查的是"确定性检查是否通过"，查不出"集成是否正确"——**这件事只能由 API 供应商自己测**。

**为什么值得关注**
第一，它给了"自带说明书"一个价格：文档从"给人看的网页"变成"给 agent 加载的基础设施"，收益是 7%→1.3% 和 -96% 搜索。以后评估一家 API 公司，得看它有没有官方插件和公开 agent 评测。
第二，**严格口径 52.9% vs 综合 90% 这个差距本身就是结论**：涉及钱、权限、合规的场景，验收标准必须按"每条 MUST"写，不能按"平均分"写。
第三，对用 agent 写支付/账务代码的团队，可施工的动作是——合并前人工跑一遍退款、争议、webhook 三条路径，把分项分当上限看。

**要打的折**：Stripe 自建 harness、自定标准、自判；评的是"规格与产物"而非运行时行为；judge 模型自己也在被测范围内；提分未披露模型版本与任务数拆分。

## 三、OpenAI 的模型重写 AMD 芯片 RTL：最高 14% PPA，部分已进送厂设计

**事件**（OpenAI 技术报告 **11/18** 发布；11/21–11/22 中英文集中扩散，本期首收）

这条严格说是"AI 写代码"跨过了软件边界。OpenAI 的模型没有去画晶体管，它改的是 **SystemVerilog RTL**——综合之前定义电路如何计算、控制、搬运数据的那一层。流程里有一步让它从 demo 变成了工程：**每改一处，用 Synopsys 的 EDA 工具做形式化验证，确认改完的电路行为与原设计完全等价**，然后才评 PPA。

**结果**
- AMD **旗舰 GPU** 的部分电路块：对"已被 AMD 工程师打磨多年、高度优化"的基线，**最高 14% 的 PPA 提升**；OpenAI 称这相当于把**约一年的工程优化量压到不足 5 个月**。
- **部分改动已并入 AMD 近期送厂制造的那版设计**，其余进了后续量产设计文件。
- 不止 GPU：AMD 用模型产出的设计在**下一代旗舰 CPU 关键模块**上自验出**个位数百分比**的 PPA 提升。
- 自研推理芯片 **Jalapeño**（与博通合作）：向量单元标准单元面积 **-13%**、矩阵单元 **-10%**；乘法器面积 **-15% 且延迟从 2 个时钟周期降到 1 个**；加法器面积 -15%、保持 2 周期。这些在硅片 bring-up 时验过，不是仿真数。Jalapeño 从 2025 年初就用 GPT-4o 参与。
- 同任务横向：在开源 RISC-V 核（PicoRV32、Ibex）上按隐藏负载的每秒指令数打分，**9,881 次测试**，GPT-6.2 Astra 平均最高，代际之间是稳定上升而不是一次性。
- 同时宣布与 Synopsys 深化合作（GPT-Synopsys），把模型接进 EDA 设计验证链，**向外部芯片设计师开放**。

**为什么值得关注**
这是"AI 改代码"第一次有产出**进了硅片**，而且改动落在最不愿意动的地方——微架构师稀缺、每改一次都要仿真验证、迭代周期以月计的环节。"形式化等价 + PPA 评估"这个门禁设计，比 14% 这个数字更值得抄：**它把"更好"和"还是一样的功能"分成了两道必须都过的关**，这正是本期其他四条缺的东西。

**要打的折（这条折最多）**
- **14% 全部来自 OpenAI 自报，全篇没有 AMD 的新闻稿或引述**；CPU 的"个位数"是 OpenAI 转述 AMD 的验证结果。
- **14% 是 PPA 层面的收益，不等于 GPU 性能提升 14%**——功耗/性能/面积各占多少，OpenAI 没拆。
- 没披露用的是哪个模型；没披露建议被 AMD 工程师驳回的比例；没确认哪些产品会用上。外界往 RDNA5/CDNA5/Zen6 上联想的，**没有任何官方说法**。
- 多家中文稿已把"高度优化的基线"这个限定语丢掉了，那是让 14% 成立还是变成营销话术的分水岭。

## 四、PhyDEX：先算清物体的重量和摩擦，再抛出去——三个 VLA 全部低于 3%

**事件**（arXiv 2611.26565，**11/20**；VinUniversity、阿肯色大学等；同期 11/20 还有众擎 Awaken-HI，两者构成同一天的两极）

PhyDEX 设计的任务很"物理"：机器人必须**先推断物体的质量、质心、摩擦**，再把它**抛到自己运动学工作空间之外**。规模不小——9 项任务、**35,357 条轨迹、143.2 小时数据**，覆盖均匀/非均匀/变质量物体，静止与移动目标。

**结果（作者自报）**

| 设定 | GR00T N1.7 | DynamicVLA | ForceVLA |
|---|---|---|---|
| 全多样性总体成功率 | **0.9%** | **0.2%** | **2.4%** |
| 人形仿真 | 6% | 0.7% | 8.7% |
| 真机（UR10e + 三只同形不同物性立方体） | 10.7% | 0% | **51.3%** |

- **约 89% 的失败发生在抛掷之前**——不是抛不准，是根本没抓好：平均只有 **21.24% 的轨迹能完成抓取**，抛出后的成功率约 **5.6%**。
- **把物体真实物理属性直接喂给模型，成功率大约翻倍**：说明模型不是"不想用"，是"读不出来"。
- ForceVLA 靠力觉在真机上做到 51.3%，但那是三只定义好的立方体，**场景远窄于全基准**。

**同一天的另一极：众擎 Awaken-HI 的 93.75%**
arXiv 2611.26420（11/20 北京时间 01:03 提交，EngineAI）：把约 **5 万小时第一视角双目视频**与**同步全身人体动作**配对成 Awaken-Human 数据集（100+ 技能），用共享 action expert **同时预测原始人体动作和重定向后的机器人动作**，再用约 **150 小时 T800 遥操作数据**后训练。

- T800 八项真机任务各 10 次，平均 **93.75%**，对比 π0.5 的 **57.5%**、GR00T N1.7 的 **58.75%**；
- **不中途复位**的长程工业补货 **90%**（两个基线 10%、30%），家庭整理 **80%**（20%、10%）；
- 人体预训练数据 5,000 → 50,000 小时，三项家庭任务 **56.7% → 90.0%**，是第一条明确的人体视频 scaling 曲线；
- 但**后训练没见过的物体**上，纸巾和药瓶的完成率掉到 **50% 和 30%**，熟悉物体配新目的地则正常。

**为什么值得关注**
93.75% 和 2.4% 出现在同一周、同一个 arXiv 分类里，这才是行业真实位置：**分布内泛化已接近可用，世界理解基本为零。** 抓得住的活靠"看人学动作"能快速收敛，需要预判物理后果的活还空白。力觉再次被证明是缺口——ForceVLA 在窄场景里靠力觉领先一个数量级，和灵巧手标准、触觉数据基建的讨论指向同一处。判断一家具身公司的能力，问一句"你们的指标是在见过的物体上还是没见过的物体上"就够了。

**要打的折**：Awaken-HI 每项只有 10 次试验、任务集自选、未开源、无第三方复现，93.75% 不能与不同任务集的分数横比；PhyDEX 三个模型都是各自微调后测的，不代表架构天花板。

## 五、智元精灵 G2 数十台进蓝思手机测试产线：赌的不是节拍，是换型

**事件**（**11/20** 第一财经、每日经济新闻先后报道；**11/21** 蓝思科技官宣）

蓝思科技与智元创新达成战略合作，在**手机测试产线**部署**数十台精灵 G2**，同时承担**测试工位自动上下料**与**与测试设备交互**，覆盖 **MMI（人机全功能）、ANT（天线射频）、CAM/CAMCV（相机基础与画质视觉）** 等工序，支持 7×24 作业。这是继龙旗南昌工厂之后，G2 第二次进 3C 测试工位。

**为什么选手机测试工位**
3C 测试有三个特征叠在一起：**动作重复度极高、机型换代快、换线频繁**。专机在极限节拍和良率上仍然赢，但**机型一换，产线改造费就得重掏一遍**。通用本体能算过账来的地方恰好不在节拍，而在"**少改造、快换型**"——数十台在工厂里不算规模，它验证的是这条商业逻辑能不能成立。

**为什么值得关注**
这是消费电子龙头**第一次把具身智能机器人写进量产工序清单**（而不是展厅或示范线）。价值不在单台动作有多顺，而在"1→N"的复制经济性：柔性本体摊薄产线改造成本，才可能真替代专机。把这条和本期其他四条放一起看也成立——它的"及格线"同样被重新定义了：**不是"能不能干"，是"换机型时要不要重新掏钱"。**

**要打的折（这条留白最多）**
- **台数只说"数十台"**，具体工厂、确切数量、**节拍、良率、成功率、人工接手频率、合同金额，一个都没披露**；
- 双方通稿都留了活口：要"完整跑通工艺适配、产线联调、交付落地全链路"才有 1→N，目前只能当**标准化样板间**看；
- 蓝思自身财务也在承压：2026 前三季营收 479.02 亿（**-10.74%**）、归母净利 14.20 亿（**-50.06%**），含具身智能的"其他智能终端"业务 2026H1 收入 5.34 亿、+46.92%，但**只占总营收 1.85%**；Q3 单季研发 9.45 亿、+18.7%。这条合作短期填不平利润表。
- 关系不是从零开始：蓝思 2024 年起就承接智元的关节模组、结构件与整机组装，双方合资湖南智启未来（蓝思出资 700 万、持股 70%），蓝思还投了智元旗下智鼎机器人；11 月新设昆山蓝思智能机器人（注册资本 1000 万）。

## 六、附注（同日值得记，但未升主条目）

**AI Coding 侧**
- **OpenRouter 撤销 125 个端点的"零留存"资格**（11/21 事件说明）：安全公司 Dragos 的"金丝雀"研究抓到提示词泄漏，暴露集中在直连或经转售商路由到 MiniMax 模型的流量上，**测试链接在推理结束 40–130 小时后仍被访问**；OpenRouter 已下架 3 家供应商、通知受影响客户，通过验证才恢复 ZDR。同期 Together AI 披露，一个 AI 编码 agent 在其公开 GitHub 仓库里提交了**能解锁私有仓库的凭据**，导致数月客户提示词暴露。"零数据留存"从此是一个带审计记录、可被撤销的标签。
- **JetBrains ThinkRail**（v0.4.0 于 **11/12**，当前 8.4k stars，Apache-2.0）：把 `pi` coding agent 当引擎、自己只做"薄宿主"；**每个 workspace 是一个 git worktree**（独立分支 + 独立 cwd），项目知识存成 `SPEC.md` 图，agent 用 `spec_*` 工具读写维护；Monaco 编辑器、每 workspace 独立终端、顶部跟 PR/CI 状态可一键合并。局限：**只支持 pi 一个引擎**、Linux 包未签名、有安装 ID 级遥测。这是"agentic IDE"第一次把隔离单位从"会话"改成"工作树"。
