**主题：今天五条消息，改的都是"接口"，不是"能力"。**

阿里把最强模型的权重接口关上了（Qwen4-Max 旗舰首次不开源）；Hugging Face 把模型后端换成一个路由（开放权重已占 71.7% 的 token）；有人把攻击入口从漏洞改成了 `.claude/settings.json` 这个配置文件；华为给世界模型补上了两个有名字的榜单和一个开源日期；一篇论文说 VLA 里那个"独立视觉编码器"本身就该被拆掉。

五条里没有一条是"分数又高了"，四条是"把某个默认设定变成可选项"，一条是"这个设定本来就是错的"。

## 主条目

### 1. Qwen4-Max 正式发布：2.4T 参数没涨，但旗舰第一次不开权

- **11/16 阿里通义千问正式发布 Qwen4-Max**（11/11 已在 Token Plan 预览两周，预览标识 **11/25 24:00 下线**）。**总参数 2.4 万亿**，每 token **激活 71B**（比上代少约 25%），另有 **328B N-gram Embedding** 参数，原生视觉、**100 万 token 上下文**、约 **39.3 万 token 输出**，兼容 OpenAI 与 Anthropic 两种 API 格式。
- **官方这轮讲的不是"更聪明"，是"更省"**——这是它和以往旗舰发布会最大的不同：

| 指标 | Qwen4-Max | 上代 Qwen3.8-Max |
|---|---|---|
| Work360 综合 | **52.69** | 47.74 |
| 单任务平均费用 | **¥11.16（≈$1.67）** | ¥26.58（≈$4.43） |
| Terminal-Bench 4.0 | **48.5** | 38.9 |
| TB4.0 每次尝试 token | **15.1 万** | 28.9 万 |
| ALE（智能体） | **46.7** | +18.8 分 |
| 缓存命中价 | **¥0.5 / 百万 token**（降约 70%） | — |
| API 标价 | $1.5 / $4.5 | $2 / $6 |

- **编程侧的两个数要分开读**：**DeepSWE v1.1 75.7 略高于 Opus 5.5 的 74.2**，但 **Terminal-Bench 4.0 只有 48.5**——落后 Opus 5.5 的 **59.6**、更落后 Kimi K3.1 的 **67.2**。也就是说它赢在"改仓库里的代码"，输在"在终端里连续跑通一长串命令"。CodeArena 前端盲测全球第六（1750 分，比上代 +74）。Artificial Analysis 智能指数 **43**（xhigh 档），比上代高 9 分、比 Kimi K3.1 Pro 低 3 分，**单任务成本低约 11%**。
- **最值得记的是许可**：**Qwen4-Max 不开权重，只走 API。这是 Qwen 系列旗舰第一次不开源。** 官方口径是"Qwen4 系列的中小尺寸模型会陆续开源"，并给了唯一一个具体型号线索：**Qwen4-27B 可在 16GB 内存设备上跑**，但没有时间表。报道称没有政府指令介入这个决定。
- **为什么值得关注**：两个月前讨论"开源逼近闭源"，前提是**最强的那个也会开**。今天这个前提在中国最强的一支产品线上被撤掉了。配合价格看会更清楚：它**降的是 token 消耗和缓存价，不是能力溢价**——这是把竞争指标从"榜单第一"换成"每个任务多少钱"的典型动作，而"不开权"正是这种商业模式的前提（开了权，按 token 收费就没有杠杆）。
  对照同日腾讯的 **Hy4 flash**：激活仅 **12B**、1M 上下文、**$0.07/$0.281** 每百万 token、缓存命中 ¥0.02，官方称单任务成本是 Hy4 的 **1/20**、DeepSeek-V4.1-Flash-1017 忙时价的 **1/8**。两家在同一天把"便宜"当成主卖点，说明这一轮比的是账本。

### 2. Hugging Face 把推理路由整体换成 OpenRouter：开放权重已占 71.7% 的 token

- **11/16 Hugging Face 公告**：Inference Providers 的**自建路由下线，改为 OpenRouter 路由**——每次调用按**实时价格、速度、可靠性**在 **80+ 供应商**里挑，失败自动换一家重试。调用方**代码不变**，继续用 HF token 和同一个 API。
- **两种 API 格式都支持**：OpenAI 的 Chat Completions / Responses，以及 Anthropic 的 Messages——**对任何 chat 模型都成立**，不管背后是哪家供应商。
- **这一条对 coding agent 是直接生效的**：文档给了 **Claude Code / Codex / OpenCode / Pi / Hermes Agent** 五套配置。Claude Code 走的是 **`ANTHROPIC_BASE_URL` 指向 HF 路由 + HF token**（token 需要 "Make calls to Inference Providers" 权限），官方推荐用 `hf-claude` 扩展，带模型选择器；Codex 走**自定义 provider**，`base_url=https://router.huggingface.co/v1`、`wire_api=responses`，官方示例 profile 里填的就是 **DeepSeek-V4.1-Flash**。
- **官方引用的结构数字（引 OpenRouter，2026/10）**：**开放权重模型在 9 月底占所服务 token 的 71.7%**，一年前（2025/10）是 **26.8%**，**7 月峰值 77.5%**；同期**开放权重的周 token 量涨了 60 多倍，闭源不到 10 倍**。本周 OpenRouter 上用量第一的模型是开放的 **DeepSeek-V4.1-Flash-1017，59.2 万亿 token**。
- **为什么值得关注**：这条和上一条是同一件事的两面。**一头在关门（Qwen4-Max 不开权），一头在把"换模型"变成改一行环境变量。**过去"用 Claude Code"隐含"付 Anthropic 的钱、跑 Anthropic 的模型"；现在这条链路可以被一个路由层接管，同一份配置在 80 家供应商之间按价格漂移。
  两个立刻要问的问题：① **行为漂移**——同一份 prompt、同一个仓库，后端从 A 换到 B 时，diff 大小和改动文件集合会变，而这件事不会出现在任何日志里（和 11/16 期 Copilot 换模型是同一个坑）；② **数据路径**——请求现在经过 OpenRouter 再分发，企业侧的零留存承诺要重新对一遍，这一层比直接连厂商多了一跳。

### 3. Google 抓到第一个"无人值守读补丁写利用"的 agent，另一条线是改 `.claude/settings.json`

- **11/16 Google 威胁情报组（GTIG）与 Mandiant 发布季度 AI 威胁报告**，标题就叫 **《Agentic Threat Activity Crosses a Significant Threshold》**。上一期（9/8）还写"尚未在野看到全自动攻击链"，这一期改口了。
- **核心案例 `exploit_agent`**：在一台暴露的 staging 服务器上发现的多智能体框架，接**多个前沿模型 + 本地模型**，任务是"**持续对流行 Web 应用做差分分析**"——比对补丁前后的代码，推出这个补丁在补什么，**写出利用，自动执行，无人工介入**。同一台服务器上还留着被窃数据，以及内网侦察、爆破、装 webshell、**删掉其他攻击者 webshell** 的脚本。环境变量文件里有一行俄语注释："LLM API keys for auto-exploitation (exploit_agent pilot)"。**Google 未归因到具体组织或国家**，也**没给成功率**。
- **被点到的样本**：一张图里它在分析 WordPress 插件 **Spectra（Ultimate Addons for Gutenberg）2.19.25** 的权限校验；受害者画像指向法国的媒体、娱乐与教育站点。**报告没说这次尝试成功**。
- **为什么是 n-day 而不是 0-day**：GTIG 的判断很实在——补丁是**有限的源材料**（两个版本代码 + release note + 已有研究），正好适合 LLM。**0-day 数量几乎没动**：2025 年月均 **8** 起、2026 年月均 **11** 起、**8 月冲到 22** 起；但从 1 月到 8 月，**披露与利用总数接近翻倍**——被压缩的是"补丁发布到可用利用"这段窗口。举证：PaperCut 两个漏洞在披露后**一天内**就有可用利用；GreyNoise 追踪的campaign 在披露**四天后**打到数百家组织，其中一起**几分钟内**拿到域管理员。
- **对开发者最该看的是另一条**：**朝鲜相关集群 MIDNIGHT NEPTUNE** 攻击北美、欧洲加密企业时，用**带 SynthID 水印的假招聘头像** + 假会议平台 + ClickFix 诱饵（让人运行"诊断修复脚本"），进去之后**改动内部仓库里的 `.claude/settings.json`**——这样**开发者一启动 Claude Code，就会去拉 SOMBERMEME 后门**。**这不需要 Claude Code 自身的任何漏洞，用的是合法的配置 hook。**
- **附带两条**：开源攻击框架已经实战化——**CAIRN**（多智能体、共享"黑板"，含美国航空航天领域目标）、**PentAGI**（8 月底–10 月初扫亚洲组织）、**ARTEX**（被单列为 **UNC7228**，与微软 STORM-0940 重叠，作者 10 月因采用面太广**撤了自己的 GitHub 仓库**，现在靠 fork 和付费版 "ARTEX PRO" 流通）；CyberStrikeAI 与 HexStrike AI 仍处试验阶段。**LLMjacking** 已成生意：Mandiant 处理过**单日超 10 万美元**、最高**100 万美元**的账单，入口是公开 GitHub 里的凭据和钓鱼拿 session token，一起案例用 **LiteLLM 沙箱逃逸 CVE-2026-40217** 把"虚拟 key"提成管理员；被盗算力在"LLM mixer"上转卖，报价 **$0.10–$25 / 百万 token**。
- **为什么值得关注**：这条把两个之前的判断连起来了。① **code agent 的成本曲线也是攻击的成本曲线**——同样一个"读 diff、写 PoC、决定往哪跳"的环节，11/16 那篇 SatisFix 在讨论它会不会自己给自己批假条，这里在讨论它已经不需要人批了。② **MCP、hooks、settings.json 这些"配置面"正在取代"漏洞面"成为首选入口**——它合法、不需要 CVE、杀毒软件不管、而且随仓库一起被 clone。团队层面今天就能做的两件事：**把 `.claude/`、`.mcp.json`、`AGENTS.md` 这类文件纳入 code review 与 CI 变更告警**；**别把 agent 的配置目录当成 dotfile 忽略掉**。

### 4. CloudRobo-WM1.2 会后数据：昨天那个 98.35%，今天有了两个有名字的榜单

- **11/16 14:00 发布会已开完**。相比昨天预告里唯一的"仿真成功率 98.35%"（无任务集、无基线），会后版本给了**可查的名字**：**RoboTwin 2.0 平均 88.98%**、**LiberoPro 2.0 平均 81.7%**，官方称两项均第一。**仍是华为云自报，未见第三方复现**；发布材料未说明打榜用的是哪个版本/参数规模的模型。
- **开源这件事从"宣布"变成了"日期"**：**11 月 30 日开放权重 + 推理与后训练代码 + 预训练最佳实践**（训练框架一并放出）。**截至发稿，权重地址与代码仓库仍未上线**——所以严格说，今天的"开源"和 11/15 期盘古那次一样，还是**承诺**，只是这次带了日子。
- **五项技术里两项是真结构改动**：**PPA（Perceive-Predict-Act）多模态世界表征**——融合 RGB 视频、语义特征、深度与点云，加**未来多模态预测监督**，目标是让"遮挡就半瞎、换视角就懵"的老问题缓解；**DualAct**——动作**由世界模型直接生成**，不再"先规划、再交给独立模块执行"。另三项：多粒度监督的预训练框架、跨本体运动建模、**四种可组合推理模式**（World Action / Expert Action × Joint / Action-only）。
- **现场演示的是工业件**：工业级搬运连续作业、**轴承毛刺清洁**、无人零售的物品上架与礼物入柜。**参数规模、支持本体数、端侧时延、价格，全部未公布。**
- **客户侧拿出了一个具体订单**：与**福龙马集团**联合研制的**智能清扫机器人已启动预售**，12 月上海开发布会；华为云供 CloudRobo 自动驾驶工具链、全域感知模型、规划模型、agent 运行时与昇腾算力，世界模型嵌在感知里做天气与路障预测。
- **一句要标注口径的话**："**80% 的中国具身智能企业选择昇腾云**"——这是华为云自述的生态渗透率/客户覆盖口径，不是第三方营收份额。
- **为什么值得关注**：把今天和昨天并排看，能看出发布会的**信息释放节奏**：预告期只放一个"98.35%"（不可核验），正日子放两个**有公开基准名**的分数（可复现路径明确），同时把"开源"从口号换成日期。**这比昨天更可信,但仍不等于被验证。**
  这里还有一个**同榜交叉**值得记：今天同步公开的 NEO-VLA（下条）在 **RoboTwin 2.0 官方 2,500 条示范设置下是 75.78**（随机化场景 69.40）。同一个榜单名，两个数字差 13 个点——**"第一"必须连同示范条数、任务集版本、是否随机化一起读**，否则这两条新闻放一起就是自相矛盾。

### 5. NEO-VLA：把 VLA 里那个"独立视觉编码器"整个拆掉，而且拆对了

- **南洋理工 S-Lab + 商汤研究院 + Ropedia**，论文《From Pixels to Actions — Towards Native Vision-Language-Action Policies》（arXiv **2611.06918**，11/16 中文圈详解）。**论文、代码、权重、数据集全部开源。**
- **改的是一个人人默认的接口**：主流 VLA 都是"图像 → CLIP/SigLIP/DINOv2 独立视觉编码器 → 语言主干 → 动作模块"。NEO-VLA 把编码器删了，**像素经轻量卷积 patch 嵌入层直接进一个 40 层、约 2B 的原生视觉语言主干**，动作专家（flow-matching）**读取主干不同深度的缓存特征**输出连续动作。默认读的是**近似均匀选取的 28 层**。
- **三个结论，第二个最反直觉**：

| 实验 | 结果 |
|---|---|
| NEO-VLA 2B，**冻结主干**，LIBERO 平均 | **90.9%** |
| NEO-VLA 2B，全量微调 | **95.3%** |
| Qwen3-VL-2B，冻结 / 全量微调 | 79.5% / 90.8% |
| **把 Qwen3-VL 的中间层特征直接开放给动作专家** | 冻结主干 **79.5% → 64.9%（掉 14.6 点）** |
| 只用动作数据后训练（不加理解数据） | RoboTwin 2.0 **Clean2Rand 掉到 10.7%**，文本能力丧失 |

- **也就是说：不是"把编码器中间层打开"就能拿到这个收益。**同样是"给动作模块更多层"，现成多模态模型直接开中间层**反而更差**；NEO-VLA 的增益来自视觉与语言**从底层联合预训练**，全量微调和单纯扩规模都只能缩小差距、消不掉差距。
- **分布外是它最强的地方**：**LIBERO-Plus 加权 89.7%**，对相机变化、噪声、光照背景明显更稳；但 **LIBERO-Pro 上"物体位置/任务目标变化"仍然差**——语义（98.0）和外观（84.3）能扛，**空间与任务泛化没解决**，这一点作者自己写明了，其他方法也一样差。
- **真机规模很小但指向清楚**：三个任务（网球放到易拉罐上 / 胶带卷+网球两级摆放 / 横放易拉罐立起插入），**每个只用 50 条示范**微调，各测 20 次（分布内、分布外各 10）。2B 模型多数任务优于 StarVLA，**与 π0.5 基本持平**。
- **为什么值得关注**：这一条的价值不在分数，在于它把"**选哪个编码器**"这个工程细节，改成了"**动作策略以什么方式接入视觉计算**"这个架构问题。对做选型的人，它提了一个很贵的问题：当供应商只给你"分布内成功率"时，你无法判断**它保留的表征是否覆盖了你这个任务需要的局部几何与状态变化**——而这个缺口，微调和扩规模都打不开。
  小注：真机只有 3 个任务、单一本体、50 条示范，**还不足以支撑"无编码器更好"的普遍结论**；但"开中间层反而掉 14.6 点"这个对照，是能被别人复现的。

## 本期判断

今天五条，讲的都是**接口**——谁被打开、谁被关上、谁被换掉、谁该被拆掉。

- **Qwen4-Max**：参数没涨（2.4T 对 2.4T，"超 3 万亿"的预期落空），**降的是 token 与缓存价**，关的是权重。以后问"这个模型强不强"要加一句"**它是按次收费还是按 token 收费**"——因为答案决定了它会不会开源。
- **HF 换路由**：`ANTHROPIC_BASE_URL` 一行，Claude Code 的模型后端就变成了 80 家供应商的市场。**便利的代价是行为漂移被藏在配置里**，这比模型换代更难归因。
- **GTIG**：攻击者没有破解 Claude Code，只是**改了它的配置文件**。这条对做 agent 的人是个提醒——你交付的不只是代码，还有一堆**会被自动执行、但不在 code review 里**的配置。
- **WM1.2**：从"98.35%（仿真，无任务集）"到"RoboTwin 88.98 / LiberoPro 81.7 + 11/30 开源"，**一天之内从不可核验走到可核验**。但同一天有另一个 2B 开源模型在同名榜单上只有 75.78——**这就是为什么必须看示范条数**。
- **NEO-VLA**：最值钱的不是 95.3%，是那个 **79.5 → 64.9** 的对照。它说明有些能力差**不是训练不够，是通路没接**。

如果只留一句：**这一周开始，"开源"和"性能"都不再是模型的属性，而是发布策略的属性**——同一家公司可以一边说"中小尺寸会开源"，一边把最强的那个锁在 API 后面；而锁不锁，取决于它想按 token 收钱还是按权重收生态。
