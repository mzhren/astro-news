**主题：11/11 一天里三个"署名栏"同时被改写——AWS 把代码作者写成 agent、OpenAI 把 Cursor 的模型选择器变成所有权战场、北京把 MTBF 2000 小时写进政府指标；而同一天两个实验都在说同一句反话：接口给得越"贴心"，越容易把失败藏起来**

---

## 主条目

### 1. AWS 开源了一个"没有人类作者"的云模拟器：400+ API 模型、200+ 服务，工程师只写规格与门禁

- **11/11 发布 AWS Emulator**（`aws-emulator`，挂在 AWS 自己的 GitHub 组织下）：在本机容器里模拟 AWS 核心 API——Lambda/计算、S3 类对象存储、DynamoDB、队列与通知、IAM、容器工具、CloudWatch 类遥测，**400 多个 API 模型覆盖 200 多项服务**，服务面按"持续扩张"设计。用途很朴素：把 agent 反复跑代码、读结果的内循环，从"真云 + 延迟 + 账单"挪到本地，顺带支持断网/气隙环境与确定性 CI。
- **真正的新闻是作者栏**：AWS 高级首席工程师 **Matt Goldberg** 在博客里把"我们团队没有写、也没有审查过任何一行代码"当成卖点；CTO **Werner Vogels** 随后专文谈"当 agent 写代码时，工程师的工作是什么"。**口径要先对齐**：官方主口径是"未编写、未审查"，Vogels 的叙述是"人类写详细规格与测试计划、agent 迭代、人类负责审查与合并，**约 90% 代码来自机器**"——两个数字同一个项目，引用时别混。
- **架构是三支 agent 队伍 + 一道门禁**，全部跑在 **Amazon Bedrock AgentCore** 上：①**写保真度测试**（从 AWS 公开 API 模型生成真实场景用例，逐条先拿真 AWS 验证过才准提交，现存**数万条**）；②**回放测试找偏差**（模拟器初始化时只是一个"能应答 438 个 API 模型但什么都不做"的空 web server，agent 蜂拥而上给每个失败提 issue，并把同根因的失败归组）；③**单 agent 修单 issue**，一个 agent 对应一个 issue。改动必须过**自动合并门禁**：编译不过直接拦、编码规范、安全（**多个安全 agent 各用不同攻击面审同一份 diff，外加一名通用代码审查者**）、保真度回归。当前是**数百个 agent 并发、每天修数千个 issue**。
- **起点是一个周末**：灵感来自今年早些时候 Anthropic 演示"给规格 + 参考实现，Claude agent 自己造出 C 编译器"；Goldberg 给 **Kiro** 写了个三步提示词（按 AWS CLI 写测试 → 迭代到测试在真 AWS 上通过 → 写一个能过同一批测试的实现），**15 分钟**拿到一版可用的 Amazon SQS；到周末结束，Kiro 已搭出其余部分的粗糙版本，**周一团队就开始用它测自家软件**，一个月内被内部采用。
- **一个被刻意公开的失败模式**：早期 agent 决定**自己写一个 Python 解释器**来支持 Lambda——技术上很硬，工程上很蠢。团队随后引导它复用现成库，等于给 agent 补了一课"编码规范"。Goldberg 的比喻是自己幼儿园时握不好蜡笔，把小组画的恐龙涂坏了——"不是恶意，是能力不够"，解法是**给 agent 一本填色本**。
- **透明度是设计的一部分**：代码以 **CC0** 发布，**完整提交历史**与 agent 提的每一条 issue 全在 GitHub；`issues/things-that-now-work` 放已修好的，`issues/things-that-do-not-work` 放**agent 自己发现、目前仍与真 AWS 不一致**的行为。更多细节留到 re:Invent。
- **另一个数字更说明问题**：Goldberg 曾用 Kiro 重建早年给 Alf 写的复制引擎，**第一次花了约 4 个月**；这次他盯了 agent **四个晚上**才发现它根本没法检查自己的结果。补齐规格与测试环境后，**重建只用了约 2 小时**。
- **为什么值得关注**：这条的分量不在"工具好不好用"，在**它把"agent 能不能写生产代码"这道争论从百分比换成了一个可下载、可跑、可审计的具名产品**。此前所有类似说法（谷歌"超四分之一新代码由 AI 生成"、微软/Anthropic 的组合口径）都是跨几千个项目的平均数；这是一次单点、公开、带全部 commit 的样本。更关键的是它给出的方法论：**能力不够时，别指望模型自己变强，去缩小它必须做对的面积**——保真度测试是"什么算对"，合并门禁是"错的不许进"。真正被稀缺化的因此不是打字速度，而是**规格写得够不够死、验收跑得够不够狠**。反过来也要看清边界：目标定义、测试通过标准的合理性、发布决策与事故响应仍在人这边，"没有审查代码"不等于"没有承担责任"。竞品侧最直接的是 **LocalStack**——平台厂商亲自下场做免费模拟器后，第三方付费档只能在广度、打磨与新特性跟进速度上跑赢，这是场很难的赛跑。

### 2. 今天（11/12）是 OpenAI 给 Cursor 的断供截止日：模型选择器成了所有权的战场

- **11/12 是 OpenAI 在 8/28 通知中设定的拟议断供日**。起因不是技术，是股权：**SpaceX 于 8/14 完成对 Anysphere（Cursor）600 亿美元收购**，两周后 OpenAI 宣布终止供应，理由写得很直白——"基于我们对 Musk 旗下公司违反合同的过往经验，**无法确信 SpaceX 会在我们的服务条款内使用这项技术**"，并称已按合同允许的最长通知期执行。
- **截至 11/11，双方都没有确认今天是否真的执行**，谈判仍在进行，OpenAI 自己把 11/12 描述为"拟议日期"而非最终日期。所以这条现在的正确读法是：**截止日已到、结果未定**，别写成"已断供"。
- **如果真的落地，实际变化比标题小**：较新的 **GPT-6 家族早已不在 Cursor 选择器里**，被移除的是剩下的选项（含 **GPT-5.6**）；OpenAI 同时表示在协议收尾期间**不会再向 Cursor 供应未来模型，包括即将推出的 Astra**。
- **Cursor 的抗压垫比想象厚**：CEO **Michael Truell** 称 OpenAI 模型约占编辑器**5% 的流量**；选择器里已有 **Claude Opus 5.5、Gemini、Grok 4.7 与自研 Composer**。**Anthropic 在 OpenAI 公告后数小时内就宣布提高 Claude 在 Cursor 内的可用算力**——这是最直接的一次"竞争对手补位"。想继续用的人可以**自带 API key**，或改用 OpenAI 自家 IDE 扩展。
- **为什么值得关注**：过去一年"模型厂商收购开发者工具"被当成渠道故事看，这条把它翻成了**供应链故事**——Cursor 在设计上是模型无关的，但只要控制权一变，无关性就由新股东决定。对团队的实操含义很具体：①把"某个模型必须在某个编辑器里"当成**架构风险**而不是偏好；②跨提供商换模型要**重跑 prompt 与验收样本**，行为差异不是线性的；③"自带 key"是逃生舱，但它把你从"产品用户"变回"API 客户"，计费与限流规则都换了一套。更长远的一层：当 IDE、评审库、编排层接连被模型厂商买走（11/05 期报过 Meta 收 Conductor、OpenAI 收 Pierre），**"我用的工具归谁"会变成选型时必须先问的一句**。

### 3. 北京把"平均无故障 2000 小时"写进了政府指标：具身智能从拼演示改成拼耐用

- **11/11 北京市经信局印发《北京市具身智能机器人产业高质量发展行动方案（2026—2028 年）》**。目标层：到 2028 年培育**不少于 5 家国际一流、10 家国内领先**的人形机器人整机企业，具身智能模型、本体与关键技术**达到国际一流**；**京津冀整机产能占全国 25%**，**关键零部件配套率超 60%**。
- **最值得逐条抄下来的是整机的"带数字硬指标"**：

| 指标 | 目标值 |
|---|---|
| 额定负载 | ≥ 自重的 **40%** |
| 平均无故障工作时间（MTBF） | **> 2000 小时** |
| 核心运动部件与末端执行器年故障率 | **< 10%** |
| 整机设计使用寿命 | **> 5 年** |
| 连续作业电池续航 | **≥ 4 小时** |

- **要素侧给的是"卡点清单"**：**不少于 100 个真实场景采集超 100 万小时**高质量数据，形成覆盖"训练→部署"全流程的数据供给范式；**新建超 5 万 P 具身智能专用算力**，并搭权威评测体系、做"具有全球影响力的具身智能模型榜单"；关键环节点名攻关**高端柔性触觉传感器、微型精密减速器、RISC-V 系统级智算芯片**、高动态负载 N 沟道 MOSFET，口径是"应布局尽布局、能适配尽适配"。
- **场景与验证**：工业/服务/特种分别形成**不少于 20 / 20 / 10 个标杆应用场景**（进产线、进养老院、进救援现场）；建**不少于 5 个**制造服务平台，覆盖可靠性、安全性、环境适应性中试验证；打造 **3–5 种国际一流整机平台**。同时明确**保留炫技那条线**——继续办人形机器人运动会与半程马拉松（赛事证明极限能力，场景要的是连续稳定，两条线并存）。
- **背景数字让这份文件不显得突兀**：工信部预计今年全国人形机器人整机产量**突破 10 万台**；智元从**第 1 万台下线到第 2 万台不到六个月**。
- **为什么值得关注**：过去两年这个行业最缺的不是指标高低，而是**指标本身**——发布会看跳舞、短视频看翻跟头、展会看握手，可靠性短板从来没进过聚光灯。MTBF 2000 小时、负载 40% 自重这类数字一旦进了政府文件，就同时变成了**采购门槛、验收口径与融资叙事**：买方可以问"你 MTBF 多少"，投资人可以问"你年故障率多少"，而回答不了的公司会突然发现自己讲的故事不在同一套坐标系里。更实际的连锁反应是**中试平台与评测榜**——耐用不是喊出来的，是试出来的；谁掌握测试台，谁就掌握了"合格"的定义权。风险也要说清：把数字写进目标不等于企业能达标，真正的检验是两三年后**这几个数字有没有变成招标文件里的硬条款**。

### 4. 蚂蚁灵波开源 LingBot-Touch：把三种触觉传感器压成同一套"触觉 Token"，也顺手证明了"硬塞触觉会变差"

- **11/10 发布、11/11 由首席科学家沈宇军撰文详解**：开源触觉基础模型 **LingBot-Touch**，把**磁触觉、视触觉、压阻式**三类主流传感信号统一为同一套"**触觉 Token**"，供不同灵巧手与动作模型直接调用——解决的是"换一只手/换一种传感器，触觉模型就得重训"这个死结。
- **数据全来自真实操作，约 4,983 小时**：人类戴触觉手套采集 **2,197 小时压阻 + 1,136 小时磁触觉**；遥操作 **Sharpa Wave 双臂**采集 **1,650 小时视触觉**。
- **真机增益是具体的**：**拧瓶盖**——Sharpa Wave 无触觉模型时成功率 **56.25%**，接入后能感知"瓶盖即将打滑"并及时调力，升到 **90%**。
- **同一组实验里还有一条更该被记住的反例**：**拉拉链**——不输入触觉模态成功率 **39%**，"**粗暴塞入**"触觉信息后**掉到 15%**。这不是触觉没用，是**触觉的用法比触觉的有无更决定成败**：信号没有对齐到动作的时间尺度上，等于给策略灌噪声。
- **架构定位**：灵波大脑 2.0 分四层——空间感知（LingBot-Vision + Depth 2.0）、动态交互（LingBot-Video + World 2.0）、**触觉感知（LingBot-Touch）**、操作执行（LingBot-VLA 2.0 + VA 2.0）。沈宇军的判断是"**VLA 和世界模型都不会是终局**"，模型应"从物理世界的需求出发，而不是被已有技术分类限定"，这也是其"具身原生"提法的由来；对通用大模型与具身基础模型的关系，给的是 **1+1>2 的协同**（前者补理解与推理，后者补物理感知与闭环操作）。
- **落地在测**：与**乐聚、钛虎**等本体厂，以及**国大药房、隆盛**等场景方做真实场景测试。
- **为什么值得关注**：触觉这条线此前在日报里出现过三次，但角度分别是硬件（10/06 EmArm 整臂皮肤、11/02 矩侨织物电子皮肤）与供应链（他山传感器进 DexUMI）。LingBot-Touch 是**表征层**的第一次：它的价值不在"多了一种传感器"，而在**把传感器差异吸收进模型内部**——这是具身领域"跨本体"难题在感知侧的同构解法，也是为什么它可以被别的灵巧手直接调用。而 39%→15% 这个反向数据，比 56%→90% 更有信息量：它说明**多模态融合不是加法**，接口给错，强信号会变成强干扰。这条经验对正在把触觉、本体状态、力控一股脑塞进 VLA 的团队，是一份现成的负面清单。

### 5. 苹果 AMP1：让通用大模型现场写 Python 开机器臂，零样本 96.3%，但"给它辅助函数"反而让最强模型变差

- **论文 11/06 上 arXiv（`2611.09892`，《On Agentic Manipulation Policies》），11/11 中文社区详解**——本条属于迟报拆解，非当日首发，但它是本月"coding × 具身"最值得看的一份实验设计。作者含 **Chen Chen、Omid Bagherieh、Matthias Müller、Vladlen Koltun** 等（苹果），代码与仿真数据公开。
- **做法与主流相反**：VLA/WAM 是"大量示教 → 学会把观察映射到动作"；AMP1 是**通用模型留在控制回路里**，在**持久 Python 解释器**中自己决定看什么、选抓取与放置几何、下发带时序的末端轨迹与夹爪指令、检查结果、重规划。harness 只提供感知、场景模型与动作执行检查，**不提供任何"选抓取/选放置"的函数**。
- **成绩**：

| 测试 | AMP1 | 基线 |
|---|---|---|
| RoboLab-120 零样本 | **85.6%**（Gemini 4 Argon）/ 82.8%（Opus 5.5） | 最强 VLA **49.2%**、最强 WAM **42.9%**、英伟达 Astranomy 74.8% |
| 真机 108 次（Franka 单臂，3 台，12 任务） | **104 次 = 96.3%**（开错误恢复）/ 94 次 = 87.0%（不开） | FLUX 3 Action **45.4%**、π0.5 **27.8%** |
| 其他 | LIBERO-PRO 95.2%、robosuite 100% | — |

  失败率相对强 VLA 基线降 **20 倍**、相对 WAM 降 **15 倍**；加**持久记忆**后 RoboDojo 双臂任务失败率再降 **4.6 倍**。
- **涌现出来的行为才是重点**：芥末瓶够不到，就**找了把木勺把它拨倒**再抓；目标被遮挡，先**搬走挡路的东西**再重扫；石榴太宽平行夹爪抓不起，就**顶在箱壁上固定、从下面兜起来**像铲车；真机动作偏了，它**比对图像与指令位置，诊断出是相机标定误差，自己改参数**继续。论文统计 1,200 个 RoboLab episode 里模型自创行为的频率：量容器 66%、诊断失败动作 39%。
- **最反直觉的一组**：在基础 harness 上加"辅助例程"（现成的抓取/放置函数），prompt 与感知完全相同——**四个最强模型全部变差，最多掉 7.5 分**（Opus 5.5 从 82.8% 掉到 75.3%），**六个最弱模型反而变好**（Qwen3.6-35B-A3B 从 14.2% 升到 31.8%），中间三个没变化。作者的解释很干净：**辅助例程会在强模型看清之前自动重试**，把"抓失败了"这件事藏起来，等于掐掉了强模型自我纠正的机会。
- **必须打的折**：**平均每次成功约 280 秒，大部分花在思考**；不能中途打断一条正在执行的轨迹，所以**动起来的物体与滑动中的抓取**仍很难；agent 有时**自以为做完了**其实没做完；弱模型离开深度图与相机标定就崩；真机只有**单臂 Franka**，双臂与移动平台未验证（尽管 harness 声称原样跨三类本体）；且它依赖 Gemini/Claude 这类**第三方模型**，能力上限部分不由苹果决定。
- **为什么值得关注**：这条把 11/07 期 uni-robot-agent（Codex/Claude Code 当机器人 runtime）从"一个能跑通的方案"推成了"**有对照实验的方法论**"。三点值得记住：①**"计划-执行-复查"闭环 > 预设技能库**，因为预设技能会限制机器人能试什么，而不可修订的计划会在场景变了之后继续错下去；②**辅助与能力是负相关的**——这是本条最锋利的地方，它对所有"给 agent 加个工具就好"的产品直觉是一个反例，也解释了为什么 11/11 期 AlphaProof 要把"生成与验收分离"当成硬设计：**任何自动兜底都可能变成自动掩盖**；③代价被明确标价：**分钟级 vs 毫秒级**。所以现实的终局大概率不是二选一——固定高频任务继续用训练好的策略，长尾新任务交给 agent，正如论文引用的另一份研究测的那样：agent 负责规划与检查，快动作交给学出来的控制器。
