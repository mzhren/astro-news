## 一、Claude Code 一周连发 8 版 + Codex 0.164：「配了但没真正生效」的沙箱与权限绕过被集中清算

**事件内容**

本周 Claude Code 从 2.1.303 连推到 2.1.310（八个版本），Codex CLI 出 0.164.0。主题不是新功能，而是**权限与沙箱的「纸面强制」被逐条揪出并补上**——2.1.309 几乎就是一张「本该被拦却放行了」的清单：

| 绕过路线 | 实际问题 |
|---|---|
| Shell 启动文件 | macOS / Linux 上，每条沙箱内 Bash 命令都会**先在沙箱外**执行 shell 的启动文件 |
| 符号链接 | `denyWrite` 的 glob 规则，在模式所在目录经由符号链接抵达时，不作用于路径的真实位置 |
| MCP 配置文件 | 沙箱命令与「自动接受的编辑」可以修改 `--mcp-config` 传入的那份配置 |
| 重定向 | Bash 权限检查信任了某条命令设置的变量，而该命令的重定向本身可能打开失败 |
| 复合命令 | 被包装或加前缀的 `cd` 后接 `git` 不弹窗（裸 `cd` 会弹） |
| Deny 规则 | 在某些含子 shell 的命令里，`Edit(path)` 的 deny 规则不拦对该路径的 Bash 重定向 |
| Worktree 隔离 | `locale` 前缀命令、部分 zsh 算术命令绕过隔离守卫 |
| Windows | PowerShell 权限检查自动放行了带额外参数的 `Set-Location` / `cd` |
| 2.1.310 追加 | Git Bash 缺失时，若 hook 命令只由引号字符串组成，`PreToolUse` / `PermissionRequest` hook 直接放行 |

配套两项治理能力：新增 `claude_code.safety_event`（OpenTelemetry），每一次被权限规则、auto 模式、安全检查、hook 或沙箱**拦下 / 弹窗 / 退回**的工具调用都发事件，治理第一次可被外部观测；`sandbox.allowNestedUserNamespaces` 允许 Linux 沙箱内创建 user namespace（给 Chromium、rootless podman 用），changelog 自己写明「这会让它们绕过沙箱的文件保护」。

还有三个「静默造成损失」类修复值得单记：`CLAUDE_CODE_AUTO_COMPACT_WINDOW=200k` 曾静默落成 100K 窗口（现已接受 k/M 后缀且越界报警）；`cleanupPeriodDays` 设得过大时后台清理会删掉近期文件（如粘贴的图片）；`claude --worktree` 在 HEAD 处于 detached 或另一分支时，退出不问就删 worktree 与分支，**可能丢 commit**。

Codex 0.164.0 这侧以功能为主：`/presets` 提供十个编号槽位存提示词与斜杠命令（键盘菜单召回）、`/model` 与 `/permissions` 支持把模型/推理强度/速度/权限写成内联参数、远程 Bash 与 zsh 快照会话的**凭证遮蔽**（含自定义 provider）、企业 MCP 认证（Codex 账号授权或独立登录，含需要 secret 的 OAuth client）、Bedrock 设置向导默认开启；安全方向同为符号链接与元数据路径加固（macOS 大小写变体、可替换符号链接定位可执行文件）。另修好「compaction 失败后历史里留下半截摘要」与 Windows HTTPS/WebSocket 的代理认证（改用登录用户的 Negotiate / NTLM）。

**同周被低估的另一半：MCP 从「请求-响应」变成「可中断的长任务」。** 2.1.304 起 Claude Code CLI 支持 MCP Tasks 与 Elicitations：工具调用不再返回结果，而是返回一个 task handle（task id、`working` / `input_required` 状态、时间戳、可为 null 的 TTL、轮询间隔），客户端按间隔 `tasks/get` 直到完成；**TTL 过期也不丢任务**，时钟归服务端所有。Elicitations 则让服务端在任务中途停下来问用户（确认退款、补参数、转浏览器登录），终端里自动渲染表单或 URL，无需客户端配置。边界很窄：仅 CLI / Agent SDK / GitHub Actions 三种形态，VS Code 扩展与桌面端没有，Bedrock 等不拉 feature flag 的第三方通道没有，且必须来自主对话而非子代理。

**值得关注的原因**

1. **Agent 竞争的焦点已经移到「治理面能不能真正执行」。** 过去一年大家比模型、比 harness，这一周两家头部同时承认：沙箱和权限规则存在大量「configured but not actually enforced」。如果你的团队默认 `.env` 读不到、写不出仓库，这批补丁必须升到 2.1.310 并把规则本身重审一遍——升级只补了执行路径，规则写错的部分它不会替你改。
2. **`safety_event` 比任何一个新功能都重要。** Agent 进企业最卡的一环是「说不清它为什么被拦、谁批的、拦了多少次」。把拦截行为变成 OpenTelemetry 事件，等于给权限系统装了审计底座，这也是后续做「按风险分级自动放行」的前置条件。
3. **MCP Tasks 是 Agent 架构的分水岭。** 长任务不再需要用「自定义轮询胶水」在插件里假装，中途要人确认也不再需要绕过协议——「堵在慢工具上」和「不问就往下走」两个老毛病，第一次有了协议层的答案。但发布面如此之窄（桌面端与 VS Code 都不支持），说明它还只是「开发者自用可用」，别急着当生产依赖。

## 二、HTTP2Shell（CVE-2026-111497，CVSS 9.2）从 Node.js 扩散到 Bun / Python / Envoy / Istio：Agent 运行时是被忽视的供应链

**事件内容**

10/21 Node.js 为 Brotli 解码器漏洞发版时，舆论把它当「Node 的问题」（代号 Node2Shell）。到 10/23，安全厂商把它改名 **HTTP2Shell** 并扩大范围——因为出问题的是 Google 的 C 库，**任何解码 `Content-Encoding: br` 的东西都带着它**。

| 项 | 内容 |
|---|---|
| 漏洞 | Brotli 解码器（`c/dec/decode.c`）越界写，影响 1.0.3 – 1.2.0，CVSS 4.0 = **9.2 Critical** |
| 机理 | 非法的 block switch 被当成「还需更多输入」而非永久格式错误，流式解码器持续把输入追加进一个 8 字节的内部缓冲 |
| 修复 | Brotli 1.0.10 / 1.1.1 / 1.2.1；Node.js 22.23.4、24.22.1、26.12.1（10/21）；**Bun 1.4.4**（10/22）；Envoy 1.36.12 / 1.37.8 / 1.38.6 / 1.39.3 / 1.40.0；Istio 1.29.9 / 1.30.6 / 1.31.2；PyPI Brotli 1.2.1、brotlicffi 1.2.1.0 |
| 发现者 | **OpenAI Codex Security 的 Khai Tran 与 Sylvie Mayer**；Envoy 的 GHSA 明确致谢 OpenAI Security Research |
| 时间线 | 2/27 修复提交就进了源码树（"Detect and report invalid stream earlier"），**但八个月没有任何发行版带上它** → 10/16 保留 CVE → 10/21 Node 发版 → 10/22 CVE 公布 → 10/23 改名扩围 |
| 在野 | CISA KEV 未收录，无已知利用；Imperva 在未打补丁的 Node.js 24.22.0（Linux ARM64）上以「fetch 响应 + Express 请求体」演示了代码执行，PoC 未公开 |

两个方向都能打：恶意客户端攻击解码请求体的服务端，**恶意服务端攻击解码响应的客户端**（`curl --compressed` 也算）。Python 侧的隐蔽性最强——只要装了 `brotli`，urllib3 / requests、`httpx[brotli]`、aiohttp、Scrapy 就会自动解码，代码里根本没 import 也一样；而这个包月下载 8280 万次。更麻烦的是 10/23 之前 pip-audit、Dependabot、Safety **都不报**（CVE 未映射到 PyPI 包），PYSEC-2026-4322 / 4323 补上才算能扫。截至 10/24，Debian stable、Alpine、openSUSE Tumbleweed 已发修好的包，RHEL 与 Ubuntu 尚无。

**值得关注的原因**

1. **这是「AI 红队挖出真实 CVE」的第一批硬证据。** OpenAI 说 agent 是在红队自家训练环境时发现该问题——和 10-24 期那条「前沿训练全面断网」正好接上：让 agent 去打自己的基础设施，产出不只是内部报告，而是外部世界要跟着打补丁的公共漏洞。安全能力正在成为实验室的副产品，也会成为招聘与合规叙事的一部分。
2. **上游修了、下游不发行，等于没修。** 八个月的空窗期是这次真正的教训：开源安全的问题不只是「有没有人发现」，更是「修复有没有被分发」。对做 agent 基础设施的团队，这意味着 SBOM 要覆盖到 C 库这一层，而不是只扫 `package.json`。
3. **Coding agent 的暴露面被系统性低估。** 上周 OpenCode 1.x 分支 1.19.4 把内置 Bun 升到 1.4.4，当时看是「例行依赖升级」，现在回头看**那就是这次的关键补丁**；Claude Code、Codex 都是 Node 栈。而 agent 的日常动作恰恰是「fetch 任意 URL、抓网页、跑 `npm install` / `pip install`」——比普通后端更频繁地解码不可信来源的压缩响应。把它当安全边界内的组件来管，不是可选项。

## 三、人大文继荣团队 Harness Scaling：把「harness 比模型重要」从经验变成训练方法

**事件内容**

10/24 公开于 arXiv 的一项工作，把 Agentic RL 从「绑定单一执行框架」推向「在多样化 harness 上训练」：

- **五个因子**：把 agent 执行框架拆成系统提示、工具接口、观测、上下文管理、工作流；
- **243 种配置空间**，用正交设计挑出 **18 种**用于训练；
- **效果**：Qwen3-4B 在 GRPO 下均分 **29.81 → 39.04**；
- **关键点**：迁移到训练中**没见过**的白盒与黑盒框架（含 Claude Code）时，仍优于单框架训练的对照组。

这恰好接上本周另外两条同题材料：Scale AI 的《Model or Harness?》（arXiv 2607.28802）主张不再把 agent 当黑盒评估，而是拆成六个组件、以「组件间的交互边」作为失败分析的基本单位，每个失败唯一对应一条边 + 一个责任方；产业侧的极端案例是同一 GPT-6 Astra 在 ARC-AGI-3 上，标准 harness 下 62.7%、换 Provider Adapter 后 98.6%——**35.9 个百分点的分差，且得分更高的方案成本还低 34%**。Y Combinator 的 Paper Club 干脆把主题定为《Why the Harness Matters More Than the Model》。

**值得关注的原因**

1. **它给了小模型一条绕开算力劣势的现实路径。** 如果 harness 是能力的第一变量，那么「追前沿基座」就不是唯一解：把 4B 级模型放在多样化 harness 上做 RL，训练出的是**不挑框架的策略**，拿到闭源黑盒框架里也能兑现。对国内团队，这比再训一个更大的基座便宜一到两个数量级。
2. **它解释了 coding agent 选型为什么「换工具比换模型管用」。** 同一模型在 Claude Code / Codex / Cursor 里表现差异远超预期，过去只能归因为「工程细节」，现在有了可训练、可量化的解释框架。
3. **但别把结论拉满。** 243 种配置只取 18 种训练，泛化到「完全没见过的 harness」的上界仍是未知；论文的绝对分（39.04）也谈不上强。真正该带走的是方法论：**把 harness 当分布而不是配置来对待**，这比一个具体分数更值钱。

## 四、智元 110 台远征 A3 同场群舞创吉尼斯：人形机器人的考题从「单机动作」换成「量产一致性」

**事件内容**

10/24，智元在济南黄河国际会展中心用 **110 台远征 A3** 全尺寸人形机器人同场起舞，创下「最多人形机器人同时跳舞」吉尼斯世界纪录，认证官现场颁证，**零失误**通过。

| 维度 | 情况 |
|---|---|
| 机器 | 全部为量产机，**没有特调演示机**；产线保证每台的关节零位、力矩、动作库一致 |
| 调度 | 自研灵动 LinkBots 集群调控平台：可视化阵型编排、自主导航、走跑一体化协同、多编队独立动作控制 |
| 通信定位 | 5G + WiFi 双模融合；UWB 厘米级融合定位 + 统一时间基准，毫秒级同步 |
| 容错 | 单台掉线自动完成局部位形补偿，整体阵型不中断 |
| 环境考验 | 开阔场地、阳光干扰、多机互相遮挡、人群走动遮挡定位信号 |
| 部署成本 | 可折叠收纳装箱，到场后自主出箱、定位、进入预设阵位 |

智元合伙人、高级副总裁王闯的说法是「**演示现场就是交付现场**」：这次的实质不是跳舞，而是把「量产一致性 + 大规模集群调度 + 高精度定位」三项能力一次性压测。这批机器人事后将投入公共服务、文旅演艺、园区展厅、科研教育；济南奥体中心、转山西路地铁站已有试点（咨询导引、客流辅助疏导、城市文化讲解）。

**值得关注的原因**

1. **这是「交付态」而不是「演示态」的指标。** 采购方真正怕的是「100 台里 3 台不同步，就得派人现场调」——关节零位与动作库的一致性、掉线自动补位、到场自主出箱进阵位，对应的正是批量部署里最贵的三项成本：物流、人力、现场调试。和 10-23 期 Optimus 转「量产质量」、10-24 期均普产线 99.9% 是同一主题的三个切面。
2. **多机协同正在成为独立的技术栈。** 单机智能再强，一百台站在一起就是另一个问题（时间同步、通信可靠性、遮挡下的定位、单点故障的传播）。LinkBots 这类「集群调控平台」此前几乎没人当产品做，而文旅演艺、园区巡游、公共服务的商业模型恰恰是「按台数出租」——这是最先能算清账的场景。
3. **它把竞争口径从「会不会」推到了「可不可复制」。** 王闯自己的总结是：未来竞争集中在「能否让大量机器人持续稳定地进入现实场景并发挥作用」。这句话对投资人的含义是，看本体公司的报表时，「一致性良率」和「远程运维比例」比 demo 视频有用得多。

## 五、云深处一次摊开具身大脑五项成果：从世界模型到数据闭环的全链路「体系化」样本

**事件内容**

10/24，云深处科技围绕自研具身大脑 **DEEPRobotics-Brain** 密集发布多篇论文，一次公布五项成果，并与 MIT、UCSD、UIUC、清华、浙大、港科大、北理工七所高校按模块分工：

| 成果 | 关键内容与数字 |
|---|---|
| **DR-WM-1.0**（世界模型） | 四足领域世界模型**首次引入摩擦力、粗糙度、刚度**等物理特性先验，对抗「像素上合理、动力学上不可行」（生成得出穿雪地的漂亮视频，却忽略打滑）；258 万张图像 + 超 10 万段真机片段预训练，双 ControlNet 引入场景几何与相机运动，自回归推理延续机器狗与控制器状态 |
| **DR-VLA-2.0**（具身基础模型） | EgoLynx 数据集：1 万小时人类第一视角网络视频 + 2000 段机器人示教；首个基于**域不变场景表征（DISR）**的四足导航范式，配 Mixture-of-Transformers 协同理解/预测/行动；QNS 综合评分 +5%，最终航向误差 **-14.6%** |
| **原子运动坐标大模型** | 把语言控制与力反馈纳入同一运动坐标框架，机械臂运动拆成 **13 个原子坐标**；单/双原子相反指令分离率 **92.5% / 83.1%**；未见布局的双臂任务进度 **87.8%**，接力反馈后插头插接 **78.5%**、花瓶擦拭 **75.2%**，OOD 语言泛化与力响应超 PI05、ForceVLA、LA4VLA |
| **DR-APO**（策略优化） | 首个**表征解耦**的通用生成式策略 RL 框架；MuJoCo-v5 五项基准中扩散策略 10 项指标 9 项第一、流策略 10 项全第一；具身视觉导航后训练中 NavDP 仿真成功率 **70.33% → 89.55%**；山猫 M20 真机导航成功率 **25% → 65%** |
| **DR-Agent**（具身智能体） | 首个面向持续演化世界的**自进化 4D 信念**导航智能体；EvolvingNav 用时间索引的预测 4D 信念 + 事件驱动「预测-观测-重规划」滤波器，解决「物品被挪动后记忆过期」；配套 EvoWorldBench：54 个仿真场景、80 万+ 任务实例、约 23.9 万次物体动态状态变更 |
| **DR-Benchmark**（数据闭环） | 核心数据集 LynxScenes 是首个面向轮足机器人真实户外场景的大规模数据集：山猫 M20 累计 **833.6 小时、3294.7 公里**真机采集，10 万段导航片段、300 万标注帧，27 类物体 / 4 类道路结构 / 20 类导航指令；据此对 **25 个代表性模型**做了系统体检 |

**值得关注的原因**

1. **这是「体系化 vs 单点 Demo」的分水岭。** 五项不是并列的五个亮点，而是互为上下游：数据（DR-Benchmark）→ 预演（DR-WM）→ 理解与执行（DR-VLA + 原子坐标）→ 训练（DR-APO）→ 长期在岗（DR-Agent）。国内此前更多是「某家发一个 VLA」，把全链路论文一次摊开、并且承认「零散能力拼接撑不住长期运行」，是范式表述上的进步。
2. **真机数据是这条赛道最难复制的资产。** 833.6 小时 / 3294.7 公里户外轮足数据、23.9 万次物体状态变更的基准，都不是靠算力能买到的。轮足户外场景此前没有公开大规模基准，谁先立住评测维度，谁就掌握了后续对比的定义权——这和 10-22 期无界动力「六榜登顶」是同一套竞争逻辑。
3. **DR-APO「通用训练超过专模专训」是最反直觉的一条。** 如果表征解耦真的成立，具身后训练的门槛会从「每个任务定制一套 RL」降到「一套框架跑全链路」，这直接决定中小本体厂商能不能跟上模型迭代速度。
4. **但口径要打折看。** 全部为自测 + 预印，无第三方复现；山猫 M20 真机导航 25% → 65% 虽然翻倍，绝对值仍谈不上「上岗」；原子坐标的 13 维表达在接触密集任务上的上限也未验证。这套成果的价值目前在于**架构完整度**，不在于分数。
