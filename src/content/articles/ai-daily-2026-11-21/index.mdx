## 一、Cursor 告诉美国国会：正在评估"逐步剔除中国开源模型"

**事件**（11/20，CNBC 独家，援引美国众议院国土安全委员会与美中战略竞争特别委员会调查报告）

Cursor 已向上述两个委员会表示，将"**探索逐步淘汰中国开发的开放权重模型（PRC-developed open-weight models），原因是地缘政治风险**"。这是它第一次在国会场合承认产品底座可能需要更换。

背景三条，缺一条都读不懂这件事的分量：
- **Cursor 现在是 SpaceX 的子公司**。SpaceX 6 月宣布正式协议收购 Cursor（Anysphere），**8 月完成交割，隐含股权估值约 600 亿美元**（全股票交易）。Cursor 同时参与 Grok 系列模型的训练，双方还公开说过要合作从零训练一个更大的模型。
- **它不是"用了别人的模型"，而是把别人的模型做成了自己的产品**。Composer 2 与 Composer 2.5 都是在月之暗面 Kimi K2.5 之上再训练出来的。所以换底座不是"少一个可选模型"，是改整条产品开发方式。
- **报告的结论比 Cursor 的表态更刺人**：中国开放权重模型被美国企业采用，主因是**成本、可定制性、以及接近前沿的性能**；美国目前"没有在市场要求的价格与性能上具备竞争力的开放权重替代品"。

**报告给出的药方**：启动"国家美国开放权重倡议"——整合公共算力、共享评测基础设施，以及让企业"合法访问"美国前沿模型用于训练；同时把 10 月那份禁止 DeepSeek 进入联邦民事机构系统的行政令**扩大到所有"中国开发的 AI 模型"，覆盖联邦信息系统与联邦合同履约**。Airbnb、DoorDash 也因使用情况被卷入调查；财政部与白宫科技政策办公室还在讨论是否要求美企**披露**使用中国模型的情况（尚未成规）。同一周，商务部 BIS 另发临时最终规则，堵中国企业经海外数据中心远程访问美国 AI 芯片。

**为什么值得关注**
这是"AI 编程工具的供应链"第一次被摆到立法层面讨论。过去一年 Coding 侧的竞争叙事是"谁的 agent 更会写"，但这条新闻说明：**头部工具的自研模型，底座可能是中国开源权重**。一旦"国籍"成为采购标准，竞争变量就从 benchmark 换成合规清单——而报告自己承认美国短期拿不出同等性价比的替代品，这个缺口只能靠"国家算力 + 共享评测 + 前沿模型合法访问"来补，本质是用补贴换时间。

**要打折看的地方**
措辞是"explore phasing out"，不是决定；**没有时间表，也没说影响哪些产品线**。报告由两个委员会单方发布，不是监管规则，距离落地还有立法与采购流程。CNBC 称 Cursor、SpaceX、DoorDash 均未回应。600 亿美元是 8 月交割的隐含股权估值（全股票），与上市公司市值不是同一口径。

洽谈阶段、未交割，估值来自匿名信源；公司未披露收入与毛利；SWE-2 Flash 打到 SWE-2 五分之一价格（11/05 期报过）本身说明这块在打价格战，高估值隐含的前提是价格战之后还能守住份额。

## 三、DuoDiscover：AI 优化代码，真正的瓶颈不是优化而是"评估"

**事件**（Google 论文，11/21 00:04 中文详解）

先看问题的量级：让 agent 去优化真实系统，**评估一次有多贵**——SWE-Efficiency 基准任务中位 15 分钟、最长 93 分钟；SOL-Exec 的 GPU 内核中位 14 分钟、最长 1 小时；vLLM 一次全量评估 85 分钟；CPU 微架构的数据预取器设计**一次评估 28 小时、涉及 1700 次模拟**。20 小时预算只够试十几次——不是 agent 不够聪明，是它没有足够的"试错次数"。

**三个机制**
1. **目标与标尺一起发现（co-discovery）**：每个 agent 自主决定优化代码的哪一块（target），再为这块现场写一个专属的快速打分脚本（论文叫 **yardstick**）。不要求绝对值准，只要求把方案按真实好坏排对序。vLLM 的例子里，一个 agent 盯上调度器的 prefill 批处理，自己写了个 decode 耗时的简化模型，几秒跑一次，而真评估 85 分钟——**内层循环几秒一轮狂试，外层几小时一轮只用来确认内层挑出的最好方案**。
2. **保真度测试（fidelity test）**：每次真实评估完成后，用 **Kendall's τ 秩相关**检验标尺的排序是否还和真实一致，只统计真实差距大于评估噪声的方案对；累计 ≥6 对且一致度达阈值才标记 validated，排序倒退则 invalidated，agent 重建标尺后再验。
3. **不做中央任务分解**：orchestrator 只做三件事——终止没进展的 agent、给有希望的方向派新 agent、把已确认的进展通告给还在跑的 agent。分工是**涌现**的，不是提前画好的。

**硬数据**

| 基准 | Claude Code | OpenEvolve | PerfAgent | DuoDiscover |
|---|---|---|---|---|
| FormulaCode（倍） | 1.778 | 1.161 | 1.774 | **2.156** |
| SWE-fficiency（倍） | 12.81 | 3.76 | 12.27 | **15.02** |
| SOL-Exec（SOL %） | 67.31 | 52.36 | 64.10 | **79.74** |
| FA4（提升 %） | 7.05 | 1.48 | 6.86 | **11.97** |
| JAXBench（倍） | 3.82 | 2.66 | 4.08 | **4.62** |
| TPU-Inference（倍） | 2.38 | 1.14 | 2.14 | **2.68** |

- **vLLM**：Claude Code 四个 agent 跑 20 小时只拿到 **1.07 倍**综合提升，p99 解码延迟与功耗都没改善；DuoDiscover **只用 7 次真实评估**拿到 **1.92 倍**，p99 解码延迟降 **2.94 倍**、首 token 延迟降 **3.61 倍**、功耗降 **21%**，吞吐不变，方案约 500 行纯系统层调度与调频逻辑。
- **成熟代码库**：SQLite **1.38 倍**、zstd **1.16 倍**，真实评估次数只有 Claude Code 的 **1/3–1/5**。
- **CPU 预取器**：**8000 个候选、16.7 天**，超过此前 ArchAgent v2 的 12000+ 候选、40 多天；**多核场景优于人类专家最佳设计**——自动化系统首次在这类任务上做到。
- **标尺本身的可靠性**：比真实评估快 **22–53 倍**，但 **41% 的代码库标尺、45% 的内核标尺在搜索过程中因漂移被判失效**。agent 扎堆同一目标的比例 **5–15%**，无协调的 Claude Code 是 **40–60%**。

**为什么值得关注**
"41% 的标尺会坏掉"看起来是坏消息，其实是这套设计最值钱的地方：**它不要求标尺永远正确，只要求系统能及时发现标尺什么时候开始撒谎**。论文反复强调的一条硬约束——**每一次标尺报告的进步，最终都必须过真实评估才算数**——恰好是当下 agent 自我改进叙事里最容易被跳过的一步：自主探索的空间可以很大，**判定权不能交出去**。对做 coding agent 的人来说，这条路线也给出了下一阶段的成本结构：瓶颈从"生成代码"移到"低成本验证代码"。

**要打折看的地方**
论文自陈两个局限：找不到可靠标尺时只能退回真实评估硬搜，此时不比普通 agent 快；建标尺 + 跑保真度测试有前期成本，**预算极紧（如只有半小时）反而不划算**。全部结果出自 Google 自己的实验环境，无第三方复现。

## 四、首届蚂蚁灵波具身大模型挑战赛：统一底座之后，比的是"数据回流几轮"

**事件**（决赛 11/14–16 于上海张江科学会堂，11/16 路演与闭幕，**11/20 由封面新闻披露细节**）
1855 支团队、3252 名选手、13 个国家、648 家高校/院所/企业报名，线上初赛后 **15 支战队、59 人**进入 48 小时线下真机决赛。**所有队伍统一使用开源模型 LingBot-VLA 2.0、统一的机器人硬件（灵犀 COBOT MAGIC 双臂）、统一推理算力与任务环境**。

三道赛题全是"脏活"：单臂抓果蔬、单臂抓化妆品放进透明盒、双臂协同清扫桌面垃圾倒进收纳筐——透明物体反光、多物体杂乱感知、双臂时序控制，正好是落地绕不开的三块硬骨头。

**四个结果比冠军名字重要**
1. **冠军 TARS（平均年龄 25 岁）82.5 分**：把"多物体杂乱场景"**降维成单物体抓取**，用小规模高精度数据规避 VLA 在杂乱环境里的感知短板。另一份英文梳理还提到它把单步训练从 15 秒压到 **3.4 秒**，48 小时内测了最多 **30 个 checkpoint**。
2. **EVA 战队 48 小时做了 7 轮数据回流，真机成功率从 10% 拉到 73.83%**。这是全场最有信息量的一个数字。
3. **第三名 SST 65.87 分，只用了 13 条补充数据**：冻结预训练主干，把任务理解交给外部 DeepSeek、语义分割单独做，只让 VLA 管执行。
4. **反直觉的一条**：盲目全参微调的队伍普遍出现**灾难性遗忘**——在静态测试台上表现很好，遇到随机化的真实条件就崩。

**行业侧表态**：蚂蚁灵波 CEO 朱兴认为具身基础模型在复刻"百模大战"的同一逻辑，长期看中国玩家会收缩到几家，**收敛之后产业才进入真正的加速期**，企业穿越周期要看"不随技术范式漂移的东西"——人才团队。上海交大李永露的总结更直接：具身智能的竞争正从"谁的演示更炫"转向"**谁能在真实约束下把成功率做上去**"。

**为什么值得关注**
统一模型 + 统一硬件 + 统一任务，本质是搭了一个**控制变量实验场**——这是国内具身领域第一次能把"落地能力"拆成可比较的工程变量（数据回流轮次、训练迭代速度、模型编排方式），而不是比本体参数。结论也有点扎心：**当底座被拉平，胜负手落在适配工程上，而适配工程的最优解是"少改模型、多接外部能力"**——SST 用 13 条数据拿第三，恰好证伪了"数据越多越好"。7 轮回流把成功率从 10% 做到 73.83%，说明眼下距离可用还差的是迭代速度，不是模型规模。

**要打折看的地方**
单一开源底座 + 单一硬件，结论不能外推到其他本体；赛题是桌面级短程操作，"降维成单物体抓取"有对赛题设计过拟合的可能；评分细则未公开，82.5 / 65.87 只能同场比较，不能跨届或跨赛引用。

## 五、东方精工：本体已"批量交付"，但毛利率 -1.20%、产能利用率不到两成

**事件**（11/19 互动平台回复，11/20 媒体解读）
东方精工回应投资者关于机器人订单的问询：控股子公司**东方元启已签约订单约 8300 万元，人形机器人已进入批量交付阶段，确认营业收入 2666 万元**（2026 半年报口径），在手订单与排产按计划推进。**同时明确：人形机器人关键核心零部件仍处于研发设计及验证阶段。**

把几个数字摆在一起，才看得清这条产业链的当下位置：

| 指标 | 数值 | 口径 |
|---|---|---|
| 签约订单 | 约 8300 万元 | 东方元启累计 |
| 已确认收入 | 2666 万元 | 2026 H1 |
| 待结转 | 约 5634 万元 | 8300 − 2666 |
| 具身智能机器人装备板块收入 | 约 0.29 亿元 | 上市公司 H1 |
| 该板块主营利润 / 毛利率 | **-35.05 万元 / -1.20%** | 上市公司 H1 |
| 产线 | 佛山，2026/3 投产，**万台级设计产能、30 分钟/台** | 设计口径 |
| 产能利用率 | 投资者推算"**不到 20%**"，公司未正面否认 | 投资者测算 |

公司画像也要说清：东方精工原本做瓦楞包装装备，2026 年 4 月完成重大资产出售、剥离瓦楞纸板生产线，主业改为智能海洋装备 + 具身智能机器人装备 + 智能包装装备三大块。2025 年 9 月与乐聚合资成立东方元启（公告口径 80%，最新工商信息 75%，新增第三方 5%），**承担乐聚"夸父"（Kuavo5）系列全尺寸人形的本体生产及组装**——乐聚出整机研发、运控算法、操作系统，东方精工出精密制造、自动化产线与供应链。前三季度营收 22.29 亿元（**-34.22%**）、归母净利 36.96 亿元（**+624.21%**），增长主要来自资产出售确认的投资收益与金融资产公允价值变动。

**为什么值得关注**
这是"量产叙事"最容易被跳过的一段。品牌方在讲千台、万台产能与场景数量，代工方在财报里给的是 **-1.20% 的毛利率、不到两成的产能利用率、关键零部件还在验证**。三件事同时成立并不矛盾：**整机可以组装下线，但决定性能与成本的关键环节还没自产**——这正是"能造出来"和"能赚钱造出来"之间的那段距离。对照本期第四条，两边的结论其实同源：**卡点都在工程与供应链，不在本体形态。**

**要打折看的地方**
数据来自互动平台回复与半年报，细分未经审计；"不到 20%"是投资者据此推算、公司只回复了"品质管控/交付周期/生产成本三项能力建设"，**不等于官方承认**；2666 万是子公司口径、0.29 亿是上市公司板块口径，两者不可相加或互相校验；公司未披露交付台数、客户结构与交付周期。
