**覆盖窗口**：2026-11-19 06:00 — 2026-11-20 06:30（北京时间）
**侧重**：AI Coding × 具身智能
**本期主线**：**今天所有进展都在回答同一个问题——把 agent 放上生产，谁按最后那一个按钮。**
OpenAI 的答案很朴素：工程师按 merge（Codex 已经能查到 70% 的因，但改动仍要人批）；Anthropic 的答案是把定价权交给公开市场（首日 +17%，但当天大盘跌 2%）；Google 的答案是把调度权交给模型、把成本交给账单（Neon 单价降 25%，单任务只降 17%）；具身侧则更直接——数据可以开源 500 万条，但模型还是读不出"盒子在桌沿内还是外"。

## 一、Anthropic 首日：一级市场定价成功，二级市场没给面子

**事件**（11/19 美东，纳斯达克全球精选市场，代码 ANT）
发行价 $83（区间上限 +6.4%），开盘首笔 **$111.50（+34.3%）**，盘中最高 **$115.10（+38.7%）**，收盘 **$97.17（+17.1%）**，较当日高点回落约 13 个百分点。按财联社口径市值 **1.27 万亿美元**（约 130.7 亿股），按全面摊薄 180.7 亿股计约 1.5 万亿。

**发行结构比首日涨幅更值得记**：
- 基础发行从 8.25 亿股**上调至 9.8 亿股**（公司售 9.5635 亿 + 老股东 2364.86 万），基础募资约 **813 亿美元**；
- 绿鞋同步扩容，超额配售权从 1.2375 亿股增至 **1.47 亿股**，含绿鞋合计售 **11.27 亿股、约 935.4 亿美元**；
- 加七家产业方按发行价认购的 **260 亿美元**无投票权股（谷歌、英伟达各 100 亿，AMD 25 亿，博通/美光/微软/台积电实体各 10 亿），总募资接近 **1200 亿美元**；
- 认购需求约 **5000 亿美元**（机构 4000 亿 + 散户近 1000 亿），约为原基础规模的 8 倍；
- 治理上设 F 类普通股，七名联合创始人组成的 Founder LLC 对一般表决事项固定握 **50.1%** 投票权——资本与控制权彻底分离。

**为什么值得关注**
这是第一次能用连续竞价的公开市场价格，去检验"前沿实验室"的估值。更关键的是**同一天的反向信号**：道指 -2.19%（6 月以来首次收于 5 万点下方）、标普 -2.02%、纳指 -2.25%、费半 -2.41%，VIX 冲至近 29（3 月以来日内新高），AMD 因 Hunterbrook 空头报告跌近 8%，英伟达连续第 6 天下跌。Anthropic 开盘的那一刻，正是各大指数砸出日内低点的时刻。**这不是"AI 行情被 IPO 带起来"，而是"IPO 成了这轮行情的兑现出口"**。Amodei 在敲钟现场的表态也值得记：会根据对安全的信心调整训练与发布节奏，"不会屈服于商业或政治压力"——这句话在上市公司语境下的可执行性，未来每个季度都会被追问。

**要打折看的地方**
- **解禁节奏比被动买盘快**。华泰按中值测算：快速纳入的被动资金约 **181–209 亿美元（中值 195 亿，占公开发行 29.7%）**，且大多落在 11 月底至 12 月；而 2026 年内就将解禁 **6.15 亿股（按 74 美元约 455 亿美元）**，是被动买盘的 **2.3 倍**。上市首日非创始人董事/高管/员工至多可售 **3.16 亿股**，占初始流通 38.3%；12 月 15 日再释放 3 亿股。154.7 亿股锁定股将在 2027 年底前分 **24 档**释放，真正的峰值在 2026 年报和 2027 一季报之后。
- 前九个月营收 **332.4 亿美元（同比约 +1200%）**、Q3 增速已放缓、利润率回落——定价隐含的前提是两年后收入到 2700 亿美元以上。
- 两个市值数字（1.27 万亿 vs 1.5 万亿）差的是股本口径，引用时必须写清是哪一种。

## 二、OpenAI 把 Codex 装进了生产流程：查得出 70% 的因，但 merge 还得人按

**事件**（11/19 08:00 UTC 官方博客，Performance Factory）
OpenAI 披露内部已运行三个多月的 "Performance Factory"：以 Codex 为核心的自动化系统，把"性能回退"从告警到恢复做成流水线。

**跑出来的数**：处理 **1700+ 起**性能回退调查，其中 **600+ 起**定位到根因（约三分之一强），平均每天 **17 起**；人工复核 100 条根因建议，**70 条**判为准确。

**流水线怎么搭的**（这才是可复制的部分）
1. 告警触发即建任务，agent 先确定"指标真正开始漂移的时刻"（常比告警早几个小时）、受影响请求、对齐到哪次部署或 feature flag，再读代码找因；
2. **另一个 Codex 会话专门负责"证伪"**——例如检查"同样没被覆盖的类似请求是否仍健康"、"回滚后指标是否恢复"。早期 agent 会在第一个看似合理的解释上停下，这个对抗评审就是为此加的；
3. 修由 agent 写、开 PR，工程师 review 并 merge；部署后**再由另一个 agent** 核对是否回到基线，只恢复一部分就关旧任务、开新任务；
4. 工程约束：**任务状态与结论存在 task 对象上、不放在 agent 的上下文里**（因此能跨 agent、跨人、跨部署交接）；agent 靠**订阅事件**（review 评论、CI 失败）被唤醒，不空转轮询；每个 agent 跑在**独立服务身份 + 最小权限**下，动作可追溯。工程师把排障经验沉淀成一个叫 `perf-forensics` 的技能，agent 复用同一套 playbook。

**为什么值得关注**
这是目前实验室公开过的最完整的一份"agent 工作流生产模板"——不是更强的模型，而是**状态机 + 一个专职说"你错了"的 agent + 判断成本最高处留给人的闸门**。它同时回答了过去两周反复出现的两个痛点：验证环节是瓶颈（对抗评审）、以及 agent 的"成功"不可信。OpenAI 自承当前瓶颈是"等工程师 merge"，并正在评估让 agent 独立上线低风险修——**那一天就是 merge 按钮移动的那天，也是这套东西从"有工头的工厂"变成"无人车间"的那天**。

**要打折看的地方**
70% 是 100 条小样本人工评级，非独立复测；修复比定位难得多（提案偏复杂、会引入新 bug），所以"600 起定位到根因"不等于"600 起被修好"；这套结论高度依赖 OpenAI 自己的代码库与可观测性栈，换到缺少完整指标/部署元数据的团队，第一步就做不了。

## 三、Gemini 4 Neon：单价降 25%，单任务只降 17%

**事件**（Google DeepMind 博客 11/18 美东，北京时间 11/19 凌晨开放）
Gemini 4 家族第四款模型，定位在 Carbon（最难长程）与 Hydrogen（最快日常）之间。$3 / 百万输入、**$0.15 缓存输入（95% 折扣）**、$15 / 百万输出，100 万上下文，Low/medium/high/xhigh 四档。已进 Gemini API、AI Studio、Gemini for Business、Antigravity，Gemini 应用里对 Pro/Ultra 开放。

**成绩（厂商口径）**：AA 智能指数 xhigh 档 **61 分（全球第三）**；**AA 编程 Agent 指数 58.6 分（第一）**；Terminal-Bench 4.1 **65.2%**；FrontierCode 2.0 默认高档 **46.2%**；SWE-sweep 在 mini-SWE harness 仅 12.8%，换到 Antigravity harness 后 **39.0%**（三倍）；Vals Index 70.9%（第二）；Agent Arena 1336（第二，4200+ 真实会话）；HLE-Diamond 71.3%；Terminal-Bench Science 70.5%；RiemannBench 84.0%。
**编排是重点**：在 Antigravity 里可当"调度员"，指挥并行的 Hydrogen 子 agent，减少重复读文件、做上下文压缩。安全侧另有 Neon for cyber：AutoBaxBench 困难档 **76%**、WebExploitBench v1.2 51.26%、SEC-bench Pro 90.5%、CWE-bench v2 70.7%（比 Carbon +3.4pp），经 Fairwind 计划定向发放；Gray Swan 提示注入基准在 xhigh 档 **0% 攻击成功率**。

**为什么值得关注**
真正的信号不是名次，而是**同一个模型既当执行者又当指挥者**。过去多 agent 编排要靠外部框架手写调度逻辑，现在调度被内建进模型层，再用四档推理做成本分层——竞争从"单模型多强"推进到"谁来做总指挥、谁来付账"。

**要打折看的地方（本期最该记住的一条）**
- 官方说 high 档单任务成本比 Carbon 低 **32%**，但**现在 Neon 其实是家族里最贵的**：Carbon/Argon 仍在促销价 $2/$10，12/1 起才涨到 $4/$20——届时 Neon 才比它们便宜 25%。有第三方按 AA 单任务口径折算，Neon $6.44 vs Carbon $7.76，**只省 17%**。单价降四分之一、单任务降六分之一，差额被"想得更久"吃掉。**选模型别看 token 单价，看跑完一个任务的总花费。**
- AA 智能指数 61 仍低于 Claude Fable 5.2 的 65；所有排名来自特定评测条件，不能外推到真实仓库。
- 除 AA/Vals/Agent Arena 外，多数分数是自家基准。

## 四、浙大 × 宇树开源 Movens-5M：500 万条动作，把"人类视频"变成机器人教材

**事件**（11/18 开源发布，论文 arXiv 2610.41877 于 10/30 挂出）
浙江大学与宇树具身智能联合实验室等团队开源预训练数据集 **Movens-5M**：**500 万条**经宇树 G1 仿真执行验证的机器人动作 + **1500 万条**人体动作，总时长 **超 1 万小时**，覆盖家务、健身、户外休闲等 **16 类场景、297 种**细粒度动作。

**做法**：五阶段自动化管线——片段生成 → 质量过滤 → 语义标注 → 动作恢复 → 物理精修；把文本、视频、语音、音乐与机器人动作做多模态对齐。训出的 **Movens-Zero** 可接受文字 / 视频示范 / 语音 / 音乐四种输入，生成 G1 全身动作并实时闭环执行，已在真机验证。

**规模曲线（最有说服力的部分）**：训练数据从 1% 扩到 100% 时，文本-动作匹配 R@3 **12.72% → 62.57%**；视频动作误差 MPJPE **132.82mm → 40.90mm（-69.2%）**；语音匹配 13.98% → 74.30%；跟踪分 0.21 → 0.72；动作专家从 64.2M 扩到 910.5M。权重与数据在 HF（`wendell0218/Movens-5M`）。

**为什么值得关注**
具身智能最短的那块板一直是数据：互联网视频海量但用不了，真机采集又慢又贵。Movens-5M 的价值是把"看视频学动作"这条**廉价路径**做成可验证、可真机跑的供给——仿真执行验证 + 物理精修用来填 sim-to-real 的沟。对中小团队，这是省掉几个月采集成本的基础设施；对行业，数据层竞争的关键从"谁有真机"转向"谁会处理视频"。

**要打折看的地方**
500 万条是规模不是质量；复杂家庭场景泛化、长程稳定性、训练数据的版权与隐私都还在；62.57% 的匹配率不等于"能上岗"。开源也会加速同质化，差异化会更快转移到硬件成本与场景渠道。

## 五、FlipTest：11 个视频世界模型，答得比瞎猜还差

**事件**（arXiv 2611.19822，11/15 提交、11/17 批次公示、11/19 中文详解）
Google DeepMind（13 位作者中 11 位）+ UT Austin + UC Berkeley，提出《The Flip Test: Video World Models Fail to Learn the World State》。

**怎么测的**：不看"生成的视频像不像"，而是构造视觉"最小对"——盒子停在桌沿内几毫米 vs 探出几毫米，一个不掉、一个掉。共 **1680 个起始帧**（10 个仿真 + 15 个真实任务）。如果模型真读出了世界状态，初始画面跨过临界点时，它的预测必须跟着翻转。

**结果**：**11 个模型全部不及格**。平均配对准确率 **18.3%**，低于二选一瞎猜的 **25%**；真实场景最好的一个 **31.3%**，仿真场景**无一超过 5.3%**。规模帮不上忙：物理 AI 专用模型 Cosmos3-Super **13.7%**，与通用模型 Wan2.2 的 14.0% 基本持平。
**最锋利的一个对照**：允许模型用**代码去测量画面**而不是"用眼睛估计"时，跨边界步骤的准确率从 **31.3% 跃升到 93.3%**。

**为什么值得关注**
这是对上一条的冷静反面。数据在狂奔（500 万条、1 万小时），但世界模型对物理状态的读取仍停在原地——**看起来合理的像素，不等于被正确持有的状态**。一个对桌沿内外预测出相同未来的模型，不能用来做基于规则的决策。而"用代码测就准"这个对照把瓶颈精确定位在**状态读取**、不是数据量，等于把"工具调用 + 精确感知"这套工程手段重新推回中心——这恰好和本期 Performance Factory 的"用工具验证而非靠感觉"是同一条思路。

**要打折看的地方**
预印本 v1，评分依赖裁判模型，作者自己标注代码与数据"expected Dec 2026"、尚未放出，所以以上数字暂不可复现；"仿真无一超过 5.3%"与"真实最高 31.3%"的落差可能与两类任务的临界粒度设计有关，需等代码才能判断。
